# 빌드브리프

HTML, CSS, JavaScript만으로 동작하는 단계별 개발 요구사항 설문입니다. 15단계, 50개 중분류, 300개 질문이 있으며 서비스 형태와 기능 선택에 맞춰 질문이 표시됩니다.

초보자도 전문가가 고려하는 선택지를 알고, 의미와 장단점을 이해한 뒤 자신의 프로젝트에 맞게 결정할 수 있도록 돕습니다.

## 버전 관리

버전 형식은 **`yymmdd.01`부터 `yymmdd.99`까지**이며 Git 태그와 GitHub Release가 버전의 기준입니다. 날짜는 **한국 시간(Asia/Seoul)**으로 발급 시점에 결정합니다.

- `main`에 변경을 푸시하거나 Pull Request를 병합하면 자동 검증 후 릴리스를 발급합니다.
- 같은 날에는 `260922.01` → `260922.02`처럼 증가하고, 다음 날짜의 첫 발급은 `260923.01`입니다.
- 같은 커밋을 재실행하면 기존 버전을 재사용합니다. 테스트 실패 시 발급하지 않습니다.
- 하루 99개를 초과하면 오류로 중단합니다. `.100`을 만들거나 기존 번호를 덮어쓰지 않습니다.
- 변경이 없는 날짜에는 버전을 만들지 않습니다. 필요한 경우 Actions에서 수동 실행할 수 있습니다.
- 태그를 삭제·이동하지 마세요. 릴리스에는 해당 커밋의 소스 ZIP·tar.gz 다운로드가 제공됩니다.

동시 실행은 순서대로 처리합니다. GitHub Actions 대기열은 최대 100개이며, 그 이상으로 취소된 실행은 나중에 재실행해야 합니다. 첫 공개 이전의 비공개 개발 기록과 운영용 배포 설정은 공개 저장소에 포함하지 않습니다. 공개 버전과 기존 호스팅 서비스의 배포 번호는 별개입니다.

## 실행

`dist/index.html`을 브라우저에서 열거나, 프로젝트 폴더에서 아래 명령으로 로컬 서버를 실행하세요.

```sh
python -m http.server 4173 --bind 127.0.0.1 --directory dist
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. 추가 패키지 설치나 빌드 과정은 없습니다.

## Cloudflare 무료 배포

Workers Static Assets로 `dist`의 정적 파일만 제공합니다. Worker 서버 코드, 데이터베이스, API 키는 필요하지 않습니다. [현재 요금 안내](https://developers.cloudflare.com/workers/static-assets/billing-and-limitations/)에 따르면 정적 파일 요청은 무료·무제한이며, Free 플랜의 [Git 빌드 한도](https://developers.cloudflare.com/workers/ci-cd/builds/limits-and-pricing/)는 월 3,000분입니다. 유료 플랜이나 별도 도메인을 구매하지 않아도 기본 HTTPS 주소로 사용할 수 있습니다. 이후 서버 기능을 추가하면 그 기능의 한도·요금을 별도로 확인하세요.

Cloudflare에서 Workers & Pages → Create application → Import repository로 이 GitHub 저장소를 연결합니다.

| 설정 | 값 |
| --- | --- |
| Worker 이름 | `buildbrief` |
| Production branch | `main` |
| Root directory | 저장소 루트 |
| Build command | `node check.cjs && node scripts/release.cjs --test` |
| Deploy command | `npx wrangler deploy` |
| 빌드 환경 변수 | `NODE_VERSION=24` |
| 공개 파일 | `wrangler.jsonc`의 `assets.directory`인 `./dist` |

Cloudflare가 GitHub push마다 자체 검증을 실행하고 성공한 커밋을 배포합니다. GitHub 버전 발급 작업과는 독립적으로 실행되므로 GitHub Actions 완료를 기다리는 방식은 아닙니다. 빌드 명령의 검증을 제거하지 마세요. 배포 경로를 저장소 루트로 바꾸면 공개할 필요가 없는 파일까지 노출할 수 있으므로 `./dist`를 유지하세요.

`dist/_headers`는 스크립트 출처 제한(CSP), 다른 사이트의 프레임 삽입 차단, MIME 형식 보호 등의 응답 헤더를 설정합니다. 외부 폰트만 허용하고 스크립트의 외부 통신은 차단합니다. 답변은 계속 사용자의 브라우저에만 저장되며, 클라우드 배포가 답변의 서버 동기화나 암호화를 추가하지는 않습니다. 사이트 주소가 바뀌면 기존 주소의 브라우저 답변은 자동 이전되지 않으므로 JSON 백업으로 옮기세요.

## 구성

- `dist/questions.js`: 대분류 → 중분류 → 질문, 설명, 선택지, 조건부 분기
- `dist/report.js`: 답변 검증, 조건 필터링, 조합 경고, Markdown·AI 프롬프트 생성
- `dist/guides.js`: 선택지별 쉬운 뜻·특징, 장점, 단점·주의점, 선택 기준과 공식 설명 링크
- `dist/app.js`: 단계 이동, 입력, 브라우저 자동 저장, JSON 백업·복원, 복사·다운로드
- `dist/styles.css`: 반응형 레이아웃과 인쇄 스타일
- `dist/index.html`: 페이지 구조

## 데이터와 동작 범위

답변은 이 브라우저의 localStorage에만 저장됩니다. 계정이나 서버 동기화는 없으며 다른 기기로 이동하려면 JSON 백업을 사용합니다. 실제 API 키·비밀번호를 입력하지 마세요. 브라우저 저장이 제한되면 안내하며 답변 백업을 사용할 수 있습니다. 다른 탭에서 변경이 감지되면 덮어쓰기를 막기 위해 이 탭의 자동 저장을 중지합니다.

기능 선택 변경으로 숨겨진 답변은 보관하지만 현재 리포트와 조합 검사에서는 제외합니다. 각 단계의 접힌 고려 사항에서 질문의 목적과 표시 조건에 쓰인 답변을 확인할 수 있습니다. 직접 입력한 실행 환경은 추가 분류로 확인하며, 자동으로 기술의 의미를 추측하지 않습니다. 다른 프로젝트를 시작하기 전 필요하면 답변을 백업하세요.

선택지의 `?`를 누르면 도움말이 열리며 답변은 바뀌지 않습니다. ‘해당 없음’은 메뉴·목록 분할·부가 기능처럼 생략 가능한 질문에만 표시합니다. 이전 백업에서 불러온 ‘해당 없음’이 더 이상 허용되지 않으면 기존 값을 보관하고 재선택을 안내합니다. 모르는 기술은 ‘AI에게 추천받기’로 남길 수 있습니다.

기능 명세는 기능마다 사용자·입력·행동·결과·실패·우선순위·완료 조건을 반복 입력할 수 있습니다(최대 30개). 일부 작성한 카드도 저장되며 기존 버전의 답변 백업을 그대로 불러올 수 있습니다.

1·2단계에서 서비스 제공 형태·가격·이용 기간을 먼저 정하고, 15단계에서 코드 공개·라이선스, 고객 이용권의 세부 규칙과 외부 코드·자료의 사용 조건을 정합니다. 오픈소스·설치형·기간제·수량 제한 선택에 따라 후속 질문이 열리며, 결제 기능 없이도 이용권을 작성할 수 있습니다. 미확인 라이선스 조건은 개발 전 확인 목록에 남습니다. 답변은 요구사항 기록이며 실제 코드 공개·라이선스 부여·법률 검토를 수행하지 않습니다.

리포트는 답변으로 구성한 문서이며 AI API를 호출하거나 기술 선택을 자동 확정하지 않습니다. 미정인 답변이 있어도 생성할 수 있으며, 개발 전 확인할 결정과 개발 중 정할 세부 사항을 구분합니다. 일부 작성한 첫 출시 기능은 확인 목록에 남기고, 추후 개발 기능은 이번 출시 범위에서 제외하도록 안내합니다. 조합 경고는 일부 일반적인 불일치를 알리는 기능이며 전체 호환성 검증은 아닙니다.

서체는 Google Fonts에서 불러오며 접근할 수 없으면 시스템 글꼴을 사용합니다. 사용자 답변을 외부 분석 서비스로 보내지 않습니다.

## 판단을 돕는 설계

질문 수를 줄이는 대신 전문가가 고려하는 주제를 단계별로 배우도록 구성합니다. 50개 중분류뿐 아니라 300개 개별 질문마다 고민하는 이유·판단 기준·다음 설계에 미치는 영향과 관련 질문을 안내합니다. 자유롭게 적어야 하는 질문에는 작성 순서 또는 입력 기준과 예시를 제공합니다. 여러 규칙을 한 칸에 적던 25개 항목은 대상별 작성표로 나누며 기존 문자열은 legacy에 원문 그대로 보관합니다. 작성표는 항목당 최대 100행이며 필수 칸이 비었거나 미정이면 확인 목록에 남습니다. 관련 질문이 현재 조건에 맞지 않으면 적용 여부부터 확인하도록 표시하며 숨긴 답변을 바꾸지 않습니다.

선택지 도움말은 뜻·작동 예시·장점·단점·적합한 상황·후속 작업을 중심으로 보여주고, 비용·구현·운영 설명은 펼쳐서 확인합니다. 내용이 없는 설명 행은 렌더링하지 않습니다. 사실이나 규모를 적는 23개 질문은 장단점 대신 입력·추정 기준과 예시를 제공합니다. `?`에서 두 선택지를 비교하거나 설명을 탐색해도 답변은 바뀌지 않습니다. 선택 이유·재검토 조건은 선택적으로 리포트에 남깁니다.

기술명을 미리 알아야 답할 수 있던 앱 기술·UI·폼 도구·비밀값 보관·외부 제공자·서버 확장·배포 복구·테스트 도구와 데이터 준비에는 대표 선택지를 제공합니다. 서비스별 기능과 정책, 데이터 관계 등은 작성 도움말에 따라 구체화합니다. 도구의 현재 지원·요금은 공식 자료에서 다시 확인하며, 특정 선택이나 작성률을 전문성 점수로 판정하지 않습니다.

진행 현황은 전체 질문 수, 현재 관련 질문 수, 선택·작성 수, 추천 요청, 미응답을 구분합니다. 추천 요청은 확정 결정이 아니며 작성률은 학습 능력이나 개발 준비도 점수가 아닙니다. 리포트에는 핵심 방향 요약과 전체 세부 답변·확인 목록을 함께 담습니다.

추천 요청으로 전환하기 전 답변은 `drafts`, 선택 이유는 `notes`로 같은 버전 1 저장·백업 파일에 보관합니다. 이전 버전 1 백업도 허용합니다. 단일 선택에서 복수 선택으로 바뀐 항목은 배열로 옮기며, 이전 선택의 의미를 단정할 수 없으면 원문을 보존하고 재선택을 안내합니다. 세션+쿠키 답변은 서로 다른 검증·저장·전달 결정으로 옮기되 토큰을 JWT라고 추측하지 않습니다.

DB 복제·전환·조회 분산, 로그인 증표 검증·보관·만료·회수, 비밀번호 해싱, 기본 및 추가 암호화·키 수명, 오프라인 충돌, API 인증과 AI 평가·보관·자료 권한 질문을 포함합니다. 제공자별 지원 여부·보안 설정·법적 조건은 실제 구현 시 공식 문서를 다시 확인해야 합니다.

## 테스트와 품질의 검증 계획

필수 흐름을 한 입력칸에 모두 나열하는 대신 `critical_tests`에서 기능별 기준을 재사용합니다. 첫 출시 기능의 사용자·입력·행동·결과·실패·완료 기준은 `feature_specs`에서 매번 연결하므로 원본 수정·삭제·출시 우선순위 변경이 즉시 반영됩니다. 추후 개발은 제외하고 우선순위 미정은 표시합니다. 사용자·역할만으로 권한을 추론하지 않으며 기존 접근 규칙과 권한 테스트 요구를 함께 보여 줍니다.

여러 기능을 잇는 추가 흐름이 필요한지 직접 선택하고, 필요한 경우 이름·시작 상태·순서·기대 결과·중간 실패를 카드별로 기록합니다(최대 100개). 추가하지 않음을 선택하면 기존 카드는 보관하되 현재 리포트에서 제외합니다. 미정과 추가 흐름 없음은 구분하며, 부분 작성한 카드는 확인 목록에 남습니다. 이것은 검증 계획으로 실제 테스트 실행이나 통과를 의미하지 않습니다.

이전 `critical_tests` 문자열은 줄바꿈과 원문을 보존하는 `legacy` 필드로 옮겨 편집·백업·리포트에 유지합니다. 새 구조는 `{ basis, flows, legacy? }`이며 기존 버전 1 저장 및 백업을 계속 지원합니다. 추천 요청으로 전환하기 전의 카드와 이전 내용도 함께 복원합니다.

선택형으로 바뀐 이전 서술형 답변은 `legacyFreeText` 문항에서 직접 입력으로 옮깁니다. 줄바꿈과 최대 6,000자 원문, 보관 중인 답변과 선택 이유를 유지하며 새 선택을 자동으로 확정하지 않습니다.

질문은 표시 조건의 부모 답변부터 묻고, 심화 질문도 원래 순서를 유지합니다. 앞에서 적은 기능·권한·복구 목표는 후속 질문에서 참조할 수 있습니다. 미응답은 확인 목록에 모으고 명세 본문에는 답변·메모·연결된 검증 기준이 있는 질문만 포함합니다.
