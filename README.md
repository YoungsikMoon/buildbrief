# 빌드브리프

HTML, CSS, JavaScript만으로 동작하는 아이디어·기획·설계 정리 도구입니다. 15단계를 요구사항 정리(1–9단계) → 설계 검토(10–14단계) → 문서로 연결(15단계)로 나눕니다. 사용자가 할 일과 결과·제약을 먼저 적고, 그 근거로 화면·서버·저장·운영 기술을 비교합니다. 서비스 형태와 기능 선택에 맞는 질문은 별도의 상세 질문 펼치기 없이 순서대로 표시됩니다.

개발자와 비개발자 모두 전문가가 고려하는 선택지를 발견하고, 의미와 장단점을 이해한 뒤 자신의 프로젝트에 맞게 판단하도록 돕습니다. 결과물은 AI와 기획·요구사항·설계 문서를 구체화할 입력 자료입니다. AI의 첫 작업은 자료 확인·추가 질문·대안 비교·문서 작성이며, 구현은 문서를 검토한 뒤 별도로 요청합니다.

## 버전 관리

버전 형식은 **`yymmdd.01`부터 `yymmdd.99`까지**이며 Git 태그와 GitHub Release가 버전의 기준입니다. 날짜는 **한국 시간(Asia/Seoul)**으로 발급 시점에 결정합니다.

- `main`에 변경을 푸시하거나 Pull Request를 병합하면 자동 검증 후 릴리스를 발급합니다.
- 같은 날에는 `260922.01` → `260922.02`처럼 증가하고, 다음 날짜의 첫 발급은 `260923.01`입니다.
- 같은 커밋을 재실행하면 기존 버전을 재사용합니다. 테스트 실패 시 발급하지 않습니다.
- 하루 99개를 초과하면 오류로 중단합니다. `.100`을 만들거나 기존 번호를 덮어쓰지 않습니다.
- 변경이 없는 날짜에는 버전을 만들지 않습니다. 필요한 경우 Actions에서 수동 실행할 수 있습니다.

- 태그를 삭제·이동하지 마세요. 릴리스에는 해당 커밋의 소스 ZIP·tar.gz 다운로드가 제공됩니다.

공개 앱 상단의 버전은 빌드한 커밋을 가리키는 Git 릴리스 태그로 채웁니다. `v260922.14`처럼 표시되며 누르면 해당 GitHub Release를 새 탭에서 엽니다. 브라우저에서 최신 버전을 조회하거나 날짜로 추측하지 않으므로, 예전 배포를 열면 그 배포의 버전이 표시됩니다. 로컬 빌드는 항상 `개발 버전`이며 Pages 미리보기도 일치하는 태그가 없으면 `개발 버전`으로 표시됩니다.

동시 실행은 순서대로 처리합니다. GitHub Actions 대기열은 최대 100개이며, 그 이상으로 취소된 실행은 나중에 재실행해야 합니다. 첫 공개 이전의 비공개 개발 기록과 운영용 배포 설정은 공개 저장소에 포함하지 않습니다. 공개 버전과 기존 호스팅 서비스의 배포 번호는 별개입니다.

## 실행

`dist/index.html`을 브라우저에서 열거나, 프로젝트 폴더에서 아래 명령으로 로컬 서버를 실행하세요.

```sh
python -m http.server 4173 --bind 127.0.0.1 --directory dist
```

브라우저에서 `http://127.0.0.1:4173`을 엽니다. 추가 패키지 설치나 빌드 과정은 없습니다.

## Cloudflare 무료 배포

Cloudflare Pages로 `dist`의 정적 파일만 제공합니다. 서버 코드, 데이터베이스, 별도 배포 API 토큰은 필요하지 않습니다. [현재 요금 안내](https://developers.cloudflare.com/pages/functions/pricing/)에 따르면 정적 파일 요청은 무료·무제한이며, Free 플랜의 [빌드 한도](https://developers.cloudflare.com/pages/platform/limits/)는 월 500회입니다. 유료 플랜이나 별도 도메인을 구매하지 않아도 기본 HTTPS 주소로 사용할 수 있습니다. 이후 서버 기능을 추가하면 그 기능의 한도·요금을 별도로 확인하세요.

Cloudflare에서 Workers & Pages → Create application → Pages → 기존 Git 리포지토리 가져오기로 이 GitHub 저장소를 연결합니다.

| 설정 | 값 |
| --- | --- |
| 프로젝트 이름 | `buildbrief` |
| Production branch | `main` |
| Root directory | 저장소 루트 |
| Framework preset | 없음 |
| Build command | `node scripts/build.cjs` |
| Build output directory | `dist` |
| 빌드 환경 변수 | `NODE_VERSION=24` |
| 공개 파일 | `wrangler.jsonc`의 `pages_build_output_dir`인 `./dist` |

Cloudflare가 `main`의 GitHub push마다 `build.cjs`를 실행합니다. 이 명령은 기존 앱 검사, 릴리스 검사, 버전 표시 검사를 통과한 뒤 `CF_PAGES_COMMIT_SHA`가 현재 체크아웃과 같은지 확인하고 해당 커밋의 원격 태그만 읽습니다. GitHub 버전 발급과 Pages 빌드는 독립적으로 시작하므로 운영 빌드는 태그를 10초 간격으로 최대 5분 기다립니다. 일치하는 태그를 얻지 못하거나 태그가 모호하면 실패해 잘못된 버전을 배포하지 않습니다. 릴리스 작업이 늦게 끝났다면 성공 후 Pages 빌드를 다시 실행하세요. 환경 변수는 [Cloudflare Pages 빌드 설정](https://developers.cloudflare.com/pages/configuration/build-configuration/#environment-variables)을 따릅니다.

버전은 `dist/index.html`의 지정한 표시 영역에만 빌드 시 반영하며 JS·CSS 파일의 콘텐츠 해시 검사와 브라우저 보안 정책은 유지합니다. 로컬 빌드는 원격 태그를 조회하지 않고 항상 개발 버전으로 표시합니다. Pages 미리보기는 일치하는 태그가 없거나 원격 조회가 불가능하면 기다리지 않고 개발 버전으로 표시합니다. 배포는 Pages가 처리하므로 별도 `wrangler deploy` 명령을 추가하지 않습니다. 배포 경로를 저장소 루트로 바꾸면 공개할 필요가 없는 파일까지 노출할 수 있으므로 `./dist`를 유지하세요.

`dist/_headers`는 스크립트 출처 제한(CSP), 다른 사이트의 프레임 삽입 차단, MIME 형식 보호 등의 응답 헤더를 설정합니다. 외부 폰트만 허용하고 스크립트의 외부 통신은 차단합니다. 답변은 계속 사용자의 브라우저에만 저장되며, 클라우드 배포가 답변의 서버 동기화나 암호화를 추가하지는 않습니다. 사이트 주소가 바뀌면 기존 주소의 브라우저 답변은 자동 이전되지 않으므로 JSON 백업으로 옮기세요.

## 구성

- `dist/questions.js`: 대분류 → 중분류 → 질문, 설명, 선택지, 조건부 분기
- `dist/report.js`: 답변 검증, 조건 필터링, 조합 경고, Markdown·AI 프롬프트 생성
- `dist/projects.js`: 여러 프로젝트의 저장 형식 검증과 기존 단일 프로젝트 이전
- `dist/guides.js`: 선택지별 쉬운 뜻·특징, 장점, 단점·주의점, 선택 기준과 공식 설명 링크
- `dist/app.js`: 단계 이동, 입력, 브라우저 자동 저장, JSON 백업·복원, 복사·다운로드
- `dist/styles.css`: 반응형 레이아웃과 인쇄 스타일
- `dist/index.html`: 페이지 구조
- `scripts/build.cjs`: 검증 실행과 배포 커밋에 맞는 앱 버전 표시

## 데이터와 동작 범위

‘내 프로젝트’에서 프로젝트를 만들고 전환하며, ‘관리’에서 이름 변경·삭제·개별 및 전체 백업을 할 수 있습니다. 각 프로젝트는 독립적인 답변·추천 요청 전 입력·메모·작성 단계를 보관합니다. 프로젝트 이름은 질문지의 이름과 동일하며 이름이 같아도 별도 ID로 구분합니다. 마지막 프로젝트를 삭제하면 빈 프로젝트가 하나 생깁니다.

답변은 이 브라우저의 localStorage에만 저장됩니다. 계정이나 서버 동기화는 없으며 다른 기기로 이동하려면 JSON 백업을 사용합니다. 실제 API 키·비밀번호를 입력하지 마세요. 브라우저 저장이 제한되면 안내하며 답변 백업을 사용할 수 있습니다. 다른 탭에서 변경이 감지되면 덮어쓰기를 막기 위해 이 탭의 자동 저장과 프로젝트 변경을 중지합니다. 저장에 실패하면 프로젝트 전환·추가·삭제를 적용하지 않아 현재 작성 내용을 백업할 수 있습니다.

프로젝트 모음은 `buildbrief.projects.v1`에 한 번에 저장합니다. 이 키가 없을 때만 이전 `buildbrief.project.v1`을 첫 프로젝트로 옮기며 이전 원본 키는 덮어쓰거나 삭제하지 않습니다. 새 저장 내용이 손상되어도 과거 단일 프로젝트로 조용히 되돌리지 않습니다. 새 모음을 저장한 뒤에는 이전 키를 다시 가져오지 않으므로 삭제한 프로젝트가 다시 나타나지 않습니다. 업데이트 전에 열었던 다른 탭도 새로고침해 같은 버전을 사용하세요.

‘이 프로젝트 백업’은 기존 `buildbrief` 버전 1 형식을 유지하고 작성 단계를 포함합니다. ‘전체 프로젝트 백업’은 `buildbrief-projects` 버전 1 형식으로 전체 모음을 보관합니다. ‘백업에서 추가’는 두 형식을 모두 읽고 프로젝트마다 새 ID를 부여해 기존 프로젝트를 덮어쓰지 않고 추가합니다. 전체 백업은 검증이 끝난 뒤 모두 함께 추가하며, 일부만 가져오지 않습니다.

저장값의 형식이 잘못됐거나 지원하지 않는 버전·이전 내용의 합산 한도 초과로 읽기에 실패하면 자동 저장을 중지해 원본을 보호합니다. 저장 안내에서 원본 문자열을 그대로 내려받고 새로 입력한 답변은 별도로 백업할 수 있습니다. 읽지 못한 저장 원본을 유효한 백업으로 복구할 때에는 확인을 거칩니다. 정상 저장마다 과거 사본을 자동 생성하는 방식은 아니므로 중요한 답변은 JSON으로 백업하세요.

기능 선택 변경으로 숨겨진 답변은 보관하지만 현재 리포트와 조합 검사에서는 제외합니다. 각 단계의 접힌 고려 사항에서 질문의 목적과 표시 조건에 쓰인 답변을 확인할 수 있습니다. 직접 입력한 실행 환경은 추가 분류로 확인하며, 자동으로 기술의 의미를 추측하지 않습니다.

선택지의 `?`를 누르면 도움말이 열리며 답변은 바뀌지 않습니다. ‘해당 없음’은 메뉴·목록 분할·부가 기능처럼 생략 가능한 질문에만 표시합니다. 이전 백업에서 불러온 ‘해당 없음’이 더 이상 허용되지 않으면 기존 값을 보관하고 재선택을 안내합니다. 모르는 기술은 ‘AI에게 추천받기’로 남길 수 있습니다.

기능 명세는 기능마다 사용자·행동·결과·우선순위를 먼저 적고 입력·실패·완료 조건을 이어서 보완합니다(최대 30개). 일부 작성한 카드도 저장되며 기존 버전의 답변 백업을 그대로 불러올 수 있습니다.

7단계에서 서비스 제공 형태·가격·이용 기간을 먼저 정하고, 15단계에서 코드 공개·라이선스, 고객 이용권의 세부 규칙과 외부 코드·자료의 사용 조건을 정합니다. 오픈소스·설치형·기간제·수량 제한 선택에 따라 후속 질문이 열리며, 결제 기능 없이도 이용권을 작성할 수 있습니다. 미확인 라이선스 조건은 기획 방향 확인 목록에 남습니다. 답변은 요구사항 기록이며 실제 코드 공개·라이선스 부여·법률 검토를 수행하지 않습니다.

리포트는 답변으로 구성한 기획·설계 입력 자료이며 AI API를 호출하거나 기술 선택을 자동 확정하지 않습니다. 미정인 답변이 있어도 생성할 수 있으며, 기획 방향을 먼저 확인할 항목과 설계하면서 구체화할 항목을 구분합니다. 일부 작성한 첫 출시 기능은 확인 목록에 남기고, 추후 개발 기능은 이번 출시 범위에서 제외하도록 안내합니다. 조합 경고는 일부 일반적인 불일치를 알리는 기능이며 전체 호환성 검증은 아닙니다.

## 기획·설계로 연결하는 흐름

기능의 이름·행동·결과·실패 안내에서 화면 후보를 가져오고, 선택한 역할 이름에서 권한표를 시작할 수 있습니다. 기능 한 개가 화면 한 개라는 분석 결과가 아니므로 합치기·나누기·누락 보완이 필요합니다. 권한은 자동 부여하지 않습니다. 사용자가 초안을 가져와 검토를 표시하고 필요한 칸을 채워야 정리 완료로 셉니다. 기존 답변은 덮어쓰지 않으며 원본이 바뀌어도 가져온 초안을 자동 변경하지 않습니다. 기능의 검증 기준은 검증 계획에서 재사용하고, 마지막 단계에서는 현재 요구에 맞는 문서 후보를 제공합니다.

접근 권한 검사·입력 검증·비밀값 보호·필요한 비밀번호 해시·기본 접근성은 기술 선택과 별개로 리포트의 기본 구현 기준에 포함합니다. 정확한 적용 범위와 구현 결과는 실제 설계·개발 과정에서 검증해야 합니다.

소스 이력 관리 도구, GitHub 등 보관 위치, 저장소 구성, 브랜치·검토·병합 방식, 버전 번호 규칙을 구분합니다. 버전 선택 뒤에는 적용 대상, 증가·초기화 조건, 발급 시점, 태그·변경 기록을 정리합니다. Git을 쓰지 않는 기존 관리 방식과 직접 입력도 허용하며 도구의 이름만으로 규칙을 추정하지 않습니다.

서비스 배포 단위(모놀리식·MSA), 프런트엔드 구성(기본 구조·기능별 구성·FSD), 백엔드 구성(계층·업무 모듈·포트와 어댑터), 업무 모델링(기능·데이터 중심·DDD)은 서로 다른 결정입니다. 선택한 구조의 적용 영역·책임·참조 경계를 후속 작성표에 남깁니다. 상태가 변하는 업무는 전환 조건과 금지할 변경을 정리하고, 기존 서비스 변경은 유지할 자료·동작과 전환·복구 기준을 연결합니다.

기술 검토의 ‘판단의 출발점’과 ‘먼저 비교’ 후보는 현재 보이는 질문에 명시적으로 답한 조건을 사용한 규칙 기반 안내입니다. 연결된 답변과 빠진 근거, 선택 뒤 확인할 일을 보여 주며 모든 기술을 미리 고르게 하지 않습니다. 원하는 기술이나 제약이 있으면 직접 기록할 수 있습니다. 비교할 후보, 조건을 먼저 확인할 후보, 사용한 답변과 더 필요한 정보를 표시합니다. 직접 입력한 기술이나 자유 서술의 뜻을 임의로 추론하지 않으며 숨겨진 과거 답변을 근거로 쓰지 않습니다. 다른 선택지를 제거하거나 자동 선택하지 않습니다. 모든 기술의 적합성을 판정하는 추천 엔진은 아닙니다.

리포트는 목표·범위, 기능·업무 규칙, 화면·API, 데이터·권한, 기술·소스 관리, 검증·운영의 문서 구성을 보여 줍니다. 주요 결정에는 기록한 선택·사용자 이유·후속 질문·비교 근거를 연결합니다. ‘사용자 선택 · 검토 전’은 검증·승인을 마친 결정과 다릅니다. 비용과 구조에 영향이 큰 일부 선택은 이유가 없으면 보완을 안내하지만 모든 답변에 장문의 이유를 강요하지 않습니다.

AI 요청문에는 원본 질문 ID, 기능별 임시 참조, 문서 구성, 미정 목록과 검토 절차를 담습니다. AI가 기능·역할·화면 또는 API·데이터·인수 기준을 연결하고 사용자 입력, AI 제안, 미확인 가정과 확정 사항을 구분하도록 요청합니다. 핵심 질문부터 검토, 전체 초안부터 검토, 기존 문서 점검의 진행 방식도 반영합니다. 링크만으로 실제 자료를 읽었다고 가정하거나 사용자 입력을 실행 권한으로 해석하지 않습니다.

이전 구현 중심의 문서 진행·미정 처리·산출물 선택은 원문을 보관한 재선택 대상으로 옮깁니다. 과거 배포 허용 답변은 백업 데이터로 보관하지만 질문과 리포트에서 제외하며 새 실행 허가로 사용하지 않습니다. 저장 형식과 프로젝트 ID는 유지하고 기존 답변·추천 요청 전 초안·메모를 보존합니다.

서체는 기기에 설치된 시스템 글꼴을 사용합니다. 사용자 답변을 외부 분석 서비스로 보내지 않습니다.

## 판단을 돕는 설계

‘출발점과 준비 자료’에서 시작 단계를 고르면 필요한 후속 질문이 바로 이어집니다. 아이디어 단계는 기존 서비스 설명·문제·기능 명세를 재사용하고, 디자인 단계는 자료 위치·적용할 화면과 버전·유지 및 조정 범위·전달 준비를 받습니다. 코드가 있거나 운영 중이면 함께 확인할 디자인 유무도 물어 디자인과 코드를 같이 전달할 수 있습니다. 코드 자료는 저장소·작업 폴더와 버전, 전달 방법, 실행 방법·결과, 현재 동작·미완성·오류를 구분합니다. 운영 중인 서비스는 접속 경로, 현재 동작과 원하는 변화, 재현 상황·확인 자료, 영향을 받는 사용자·데이터·연동을 추가로 정리합니다. 직접 입력한 시작 상태에도 자료와 전달 방법을 받습니다.

이 자료들은 기존 상태와 변경 범위를 파악할 근거이므로 미응답·미정·작성표의 필수 빈칸을 우선 확인 목록에 둡니다. 기존 `existing_code` 자유 작성 원문은 작성표의 `legacy`로 보존하며 초안·메모도 유지합니다. 기존 설명만 있을 때는 지우거나 내용을 추측해 나누지 않고 세부 작성표 확인을 안내합니다. 단계 변경으로 숨긴 자료는 프로젝트와 백업에 유지하되 현재 리포트에서 제외합니다. 링크·경로 입력은 파일 업로드나 열람 확인이 아니며, 실제 AI 도구에서 별도 파일 전달·접근 확인이 필요함을 도움말과 리포트에 명시합니다.

전문가의 고려 사항을 단계별로 배우되 같은 답변을 다시 요구하거나 적용되지 않는 결정을 강요하지 않습니다. 중분류와 개별 질문마다 고민하는 이유·판단 기준·다음 설계에 미치는 영향과 관련 질문을 안내합니다. 자유롭게 적어야 하는 질문에는 작성 순서 또는 입력 기준과 예시를 제공합니다. 복잡한 내용은 대상별 작성표로 나누며 기존 문자열은 legacy에 원문 그대로 보관합니다. 작성표는 항목당 최대 100행이며 필수 칸이 비었거나 미정이면 확인 목록에 남습니다. 관련 질문이 현재 조건에 맞지 않으면 적용 여부부터 확인하도록 표시하며 숨긴 답변을 바꾸지 않습니다.

선택지 도움말은 뜻·작동 예시·장점·단점·적합한 상황·후속 작업을 중심으로 보여주고, 비용·구현·운영 설명은 펼쳐서 확인합니다. 내용이 없는 설명 행은 렌더링하지 않습니다. 사실이나 규모를 적는 질문은 장단점 대신 입력·추정 기준과 예시를 제공합니다. `?`에서 두 선택지를 비교하거나 설명을 탐색해도 답변은 바뀌지 않습니다. 선택 이유·추가 설계 메모는 선택적으로 리포트에 남깁니다.

기술명을 미리 알아야 답할 수 있던 앱 기술·UI·폼 도구·비밀값 보관·외부 제공자·서버 확장·배포 복구·테스트 도구와 데이터 준비에는 대표 선택지를 제공합니다. 서비스별 기능과 정책, 데이터 관계 등은 작성 도움말에 따라 구체화합니다. 도구의 현재 지원·요금은 공식 자료에서 다시 확인하며, 특정 선택이나 작성률을 전문성 점수로 판정하지 않습니다.

진행률은 현재 관련된 요구사항 중 정리 완료한 비율입니다. 기술 검토 항목과 기술 선택 기록은 별도로 표시하며 기술을 고르지 않았다고 요구사항 작성률을 낮추지 않습니다. 프로젝트 목록과 리포트에도 같은 요구사항 기준을 적용합니다. 기술 미선택은 리포트에 ‘설계 검토 예정’으로 남고, 실제로 고른 기술도 적합성을 검증한 결정으로 간주하지 않습니다. 자유 입력의 정확한 `미정`, `아직 대상 미정` 선택지와 구조화된 카드의 미완성 필수 칸은 확인 목록에 남습니다. `없음`이나 문장에 우연히 포함된 ‘미정’은 임의로 미결정으로 바꾸지 않습니다. 참고 자료·기존 브랜드·추가 인수 조건 등의 선택 참고 정보는 작성률에서 제외하며, 빈칸은 미결정 목록에 넣지 않습니다. 작성한 참고 정보는 리포트에 포함하고, 과거에 명시적으로 추천을 요청한 항목과 일부 작성한 추가 권한 규칙은 확인 대상으로 남깁니다. 추천 요청은 확정 결정이 아니며 작성률은 학습 능력이나 개발 준비도 점수가 아닙니다. 리포트에는 핵심 방향 요약과 전체 세부 답변·확인 목록을 함께 담습니다.

추천 요청으로 전환하기 전 답변은 `drafts`, 선택 이유는 `notes`로 같은 버전 1 저장·백업 파일에 보관합니다. 이전 버전 1 백업도 허용합니다. 단일 선택에서 복수 선택으로 바뀐 항목은 배열로 옮기며, 이전 선택의 의미를 단정할 수 없으면 원문을 보존하고 재선택을 안내합니다. 세션+쿠키 답변은 서로 다른 검증·저장·전달 결정으로 옮기되 토큰을 JWT라고 추측하지 않습니다.

DB 복제·전환·조회 분산, 로그인 증표 검증·보관·만료·회수, 비밀번호 해싱, 기본 및 추가 암호화·키 수명, 오프라인 충돌, API 인증과 AI 평가·보관·자료 권한 질문을 포함합니다. 제공자별 지원 여부·보안 설정·법적 조건은 실제 구현 시 공식 문서를 다시 확인해야 합니다.

입력 화면 유무·이용권 배정 여부·배경 작업의 신뢰성 필요를 먼저 구분해 적용되는 세부 규칙만 작성하게 합니다. 기기 파일 저장·조회 전용 오프라인·동기화 없는 기기 전용 앱·제공자 관리 DB·비밀값 없음·외부 제공자 없음도 명시할 수 있습니다. 상품 정기 결제는 청구 재시도와 상품 제공 보류를 정하고, 직접 입력한 가입 정책의 제한 규칙도 리포트에 연결합니다. 버전 보관을 선택하면 최종본 결정 기준을 별도로 확인합니다. 새 적용 여부를 답하지 않은 과거 기록은 보관하고 미정 사항으로 확인하며, 앞선 선택과 충돌하는 구성은 조합 경고로 알립니다.

## 테스트와 품질의 검증 계획

필수 흐름을 한 입력칸에 모두 나열하는 대신 `critical_tests`에서 기능별 기준을 재사용합니다. 첫 출시 기능의 사용자·입력·행동·결과·실패·완료 기준은 `feature_specs`에서 매번 연결하므로 원본 수정·삭제·출시 우선순위 변경이 즉시 반영됩니다. 추후 개발은 제외하고 우선순위 미정은 표시합니다. 사용자·역할만으로 권한을 추론하지 않으며 기존 접근 규칙과 권한 테스트 요구를 함께 보여 줍니다.

여러 기능을 잇는 추가 흐름이 필요한지 직접 선택하고, 필요한 경우 이름·시작 상태·순서·기대 결과·중간 실패를 카드별로 기록합니다(최대 100개). 추가하지 않음을 선택하면 기존 카드는 보관하되 현재 리포트에서 제외합니다. 미정과 추가 흐름 없음은 구분하며, 부분 작성한 카드는 확인 목록에 남습니다. 이것은 검증 계획으로 실제 테스트 실행이나 통과를 의미하지 않습니다.

이전 `critical_tests` 문자열은 줄바꿈과 원문을 보존하는 `legacy` 필드로 옮겨 편집·백업·리포트에 유지합니다. 새 구조는 `{ basis, flows, legacy? }`이며 기존 버전 1 저장 및 백업을 계속 지원합니다. 추천 요청으로 전환하기 전의 카드와 이전 내용도 함께 복원합니다.

선택형으로 바뀐 이전 서술형 답변은 `legacyFreeText` 문항에서 직접 입력으로 옮깁니다. 줄바꿈과 최대 6,000자 원문, 보관 중인 답변과 선택 이유를 유지하며 새 선택을 자동으로 확정하지 않습니다.

질문은 표시 조건의 부모 답변부터 묻고, 현재 적용되는 질문을 모두 원래 순서로 표시합니다. 상세 질문 스위치와 심화 질문 묶음은 두지 않습니다. 앞에서 적은 기능·권한·복구 목표는 후속 질문에서 참조할 수 있습니다. 미응답은 확인 목록에 모으고 명세 본문에는 답변·메모·연결된 검증 기준이 있는 질문만 포함합니다.

중복 질문 10개와 사용 경험 질문을 제거했습니다. 기능 목록·관리자 업무는 기능 명세의 메모에, 공통 완료 조건은 최종 인수의 추가 조건에, 별도 화면·알림 목록은 해당 작성표의 기존 내용에 합칩니다. 나중에 검토할 기능은 이번 개발 범위와 구분한 표시로 제외 범위에, 변경 금지·실행 버전 조건은 필수 조건에, 구조 선택 이유는 구조의 공통 메모에 연결합니다. 기존 답변·추천 전 입력·선택 이유는 출처와 상태를 구분하고 대상에 이미 있던 내용도 보존합니다. 목록에서 기능의 입력·행동·결과나 화면·알림의 세부 규칙을 자동으로 추측하지 않으며, 세부 표 없이 이전 목록만 옮겨 온 경우에는 보완 대상으로 남깁니다.

마이그레이션은 브라우저 불러오기와 JSON 복원에 쓰는 `normalizeProject`에서 수행하며 반복해도 내용을 중복 추가하지 않습니다. 이전 조건에서 숨겨진 관리자 업무·화면·알림·웹/서버 버전은 현재 요구로 되살리지 않고 백업에 보관합니다. 사용 경험(`known_stack`)도 기존 답변·초안·메모를 백업에 유지하지만 질문·작성률·리포트에는 넣지 않습니다. 추천 상태인 대상에 합칠 실제 원문은 복원용 초안에 보관하고, 기존 확정 내용과 섞인 이전 추천 요청은 미정 표시로 남깁니다. 통합 길이 한도는 대상별로 확장하되 기능 카드의 개별 입력은 기존 6,000자 제한을 유지합니다.

참고 서비스와 디자인 자료는 한 곳에서 입력합니다. 이전 `design_reference` 답변·메모·보관 중인 답변은 `references`에 원문을 표시해 합치며, 기존 두 칸의 최대 길이를 보존하도록 통합 칸은 13,000자까지 지원합니다. 이전 추천 요청은 복구할 참고 자료와 함께 유지합니다. 기존 백업 형식과 브라우저 저장 버전 1을 계속 사용합니다.

API만 제공하는지 사람용 화면도 제공하는지, 결제가 소프트웨어 이용 권한을 부여하는지, 이용권 축소 시 기존 자료가 남는지를 먼저 확인합니다. 화면 없는 API의 화면·스타일 질문, 저장하지 않는 서비스의 DB 선택, 기기 안에서만 실행하는 앱의 서버 호스팅·도메인 질문은 제외합니다. 기본 역할표를 먼저 작성하고 추가 접근 예외만 선택적으로 적으며, 화면·서버·파일·검색·검증 계획에서 같은 권한 기준을 참조합니다. 숨긴 답변은 백업에 유지하고 현재 리포트에서는 제외합니다.
