# 검증 절차와 이력

[보안 목차](../../SECURITY.md) · [적용 범위·상태 기준](scope.md)

수정한 보안 동작을 검증하거나 점검 상태를 갱신할 때 읽습니다. 실행 명령은 저장소 루트 기준입니다. 점검 항목의 현재 상태는 각 담당 모듈에, 수행한 검증의 기록은 이 문서에 남깁니다.

## 변경 검토와 자동 검사

- 자유 입력의 `<`·따옴표·한글을 무조건 삭제하는 방식으로 XSS를 막지 않습니다. 출력 문맥에 맞게 인코딩합니다. HTML 편집을 도입한다면 유지 관리되는 정화 도구를 검토합니다.
- CSP를 통과시키려고 인코딩을 제거하거나 `unsafe-inline`·`unsafe-eval`을 추가하지 않습니다. 공개 파일·의존성·외부 요청 검사가 실패하면 변경 이유와 위험을 먼저 검토합니다.
- `.gitignore`는 강제로 추가한 파일·다른 이름의 비밀 파일·기존 Git 이력을 보호하지 않습니다. 앱에 외부 런타임 의존성이 없더라도 빌드 도구와 호스팅 공급망은 검토합니다.
- 다음 기존 검사를 실행합니다. 검사 수를 ASVS 통과 항목 수로 표현하지 않습니다.

```sh
node check.cjs
node scripts/release.cjs --test
node scripts/build.cjs --test
```

## 관련 기능 변경 시 수동 확인

실제 이용자 자료가 없는 별도 브라우저 프로필이나 테스트용 출처·프로젝트에서 진행합니다. 공격 문자열·큰 파일·저장 차단 시험으로 운영자의 작성 자료를 손상시키지 않습니다.

| 바꾼 부분 | 최소 확인과 기대 결과 |
| --- | --- |
| 입력·렌더링·초안 | 따옴표, `<img src=x onerror=alert(1)>`, `</textarea><script>alert(1)</script>`, Markdown 제목·링크 구문을 답변·메모·카드·프로젝트 이름에 입력. 실행·새 HTML 요소·질문 경계 위조 없이 글자로 표시되고 복사·파일 출력에서도 경계가 유지됨. CSP 차단만 보고 이스케이프가 안전하다고 결론 내리지 않음. |
| URL | 정상 HTTP(S)·한글 주소, `javascript:`·`data:`·계정 정보 포함 주소·제어 문자·역슬래시·중간 공백·길이 초과를 확인. 부적합한 URL은 초안에 포함되지 않지만 편집 중 원본은 보존. 어떤 URL도 자동으로 요청하지 않음. |
| 백업·저장 | 정상 단일/전체 백업 왕복, 잘못된 JSON·형식·중복 ID·프로토타입 키·상한 초과 파일, 저장 공간 부족·저장 차단·두 탭 편집·새로고침 확인. 거부 시 원본 유지, 성공 시 답변과 선택 이유 유지, 실패 상태를 성공처럼 표시하지 않음. |
| 파일·헤더·배포 | 빌드 결과 목록 확인 후 HTTPS 운영 응답의 CSP·HSTS·MIME·프레임·참조 정책 확인. HTTP·Pages 주소·없는 경로도 확인. 민감 경로는 상태 코드뿐 아니라 응답 내용 확인. 기본 로컬 서버에는 `_headers`가 적용되지 않음. |
| 의존성·권한·운영 | 버전·SHA·출처·권한 변경 이유, 알려진 취약점과 기한 기록. 비밀값을 노출하지 않는 설정 확인 기록을 남기고 알림·롤백 등 실제 동작이 필요한 항목은 시험 결과 기록. |
