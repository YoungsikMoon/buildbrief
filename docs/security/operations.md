# 운영 점검과 남은 작업

[보안 목차](../../SECURITY.md) · [적용 범위·상태 기준](scope.md) · [검증 절차·이력](verification.md)

GitHub·Cloudflare·도메인 계정, 배포 권한, 기록·알림·복구·비용·제보를 점검하거나 남은 작업의 우선순위를 정할 때 읽습니다. 담당 항목: **OPS-01~08**.

## 운영 점검표

담당은 **저장소·Cloudflare·도메인 관리자**입니다. 아래 항목은 코드만 보고 확인할 수 없어 모두 미점검으로 시작합니다. 제품 ASVS 요구사항과 별개로 필요한 운영 통제도 포함합니다. 계정 설정을 확인하지 않은 채 V6·V8을 충족했다고 표시하지 않습니다.

| ID | 확인할 사항과 완료 근거 | 상태 |
| --- | --- | --- |
| OPS-01 계정 보호 | GitHub·Cloudflare·도메인 등록 계정의 강한 MFA 또는 패스키, 복구 수단, 활성 세션·구성원 검토. 날짜와 확인한 설정을 기록하고 비밀값·복구 코드는 문서에 넣지 않습니다. | 미점검 |

| OPS-05 기록·알림 | GitHub·Cloudflare에서 계정/권한·배포·DNS 변경을 어디에 얼마나 기록하고 누가 볼 수 있는지 확인합니다. 담당자, 이상 변경·배포 실패의 알림 경로를 정하고 알림 전달을 시험합니다. 답변·백업·비밀값은 기록하지 않습니다. ASVS V16 검토에 연결합니다. | 미점검 |
| OPS-06 장애·복구 | 정상 릴리스로 복구하는 방법과 권한을 확인하고, 별도 테스트 환경에서 재배포·백업 복원을 시험합니다. 복구 대상은 코드와 이용자 자료로 구분합니다. 서버가 이용자 답변의 사본을 보유한다고 가정하지 않습니다. | 미점검 |
| OPS-07 악용·비용 | Pages의 사용 한도·트래픽/비용 알림·DDoS 대응 범위를 확인합니다. 정적 사이트의 방어가 미래 API·AI 과금 남용까지 보호한다고 가정하지 않습니다. | 미점검 |
| OPS-08 비공개 제보 | 실제 사용할 비공개 취약점 제보 경로와 담당자·회신 절차를 정하고 전달을 시험합니다. GitHub 비공개 취약점 제보 기능이 활성화돼 있다고 가정하지 않습니다. | 미점검 |

## 먼저 처리할 남은 일

1. **운영 권한과 유출 대응:** OPS-01~03을 확인합니다. 배포 계정 탈취는 이용자 브라우저의 답변 유출로 이어질 수 있습니다.
2. **보관할 자료의 범위:** BB-14~17의 민감도·평문 저장 한계·사본 삭제 정책을 확정합니다. 기밀 자료 보관을 지원한다면 구현 전 보호 수단과 복구 방식을 설계합니다.
3. **실제 배포와 복구:** BB-13, OPS-04~08의 설정·기록·알림·복구·제보 경로를 확인합니다.
4. **입력·실패·자원 한계:** BB-01·07·09·21의 입력 경로별 검증, 큰 백업, 저사양 기기, 동시 편집, 저장 불가 시나리오를 검증하고 재현된 문제를 수정합니다.

미점검은 취약점 발견과 같은 뜻이 아닙니다. 실제 위험을 확인한 경우 영향·재현 조건·완화책·담당자·기한을 기록합니다. 민감한 상세 내용은 공개 PR이나 이슈에 넣지 않습니다.

각 항목의 현재 상태와 근거는 해당 담당 문서에서만 갱신합니다. 여기서는 우선순위와 연결할 ID를 관리합니다.

- BB-01~10: [입력·출력·백업](input-output.md)
- BB-11~17: [브라우저·통신·자료 보호](browser-data.md)
- BB-18~22: [코드·배포·공급망·오류](code-and-delivery.md)

## 유지 관리 기준

- **PR마다:** 해당 ID와 확장 조건을 검토하고 결과를 적습니다. 기능과 무관한 항목을 형식적으로 모두 체크하지 않습니다. 보안 검토가 필요 없는 문서·문구 변경은 그 이유를 적습니다.
- **배포·환경 변경 시:** 해당 헤더·공개 파일·권한·로그를 재확인합니다. 백엔드·로그인·자료 보호 방식 변경 전에는 ASVS 적용 범위와 위협 경계를 다시 정합니다.
- **월 1회 및 보안 공지 발생 시:** 관리자가 Node·GitHub Actions·Cloudflare 관련 공지와 ASVS의 새 안정판을 확인하고 결과를 기록합니다. 이 문서는 일정을 정한 것이며 자동 점검이나 알림을 설정한 것은 아닙니다. 버전 고정은 취약점 업데이트를 대신하지 않습니다.
- **수정 목표:** 프로젝트 운영 목표로, 악용 중이거나 비밀값·배포 권한 노출이면 즉시 차단·폐기·복구부터 진행합니다. 적용 가능한 높은 위험은 7일, 중간 위험은 30일, 낮은 위험은 90일 이내 수정을 목표로 합니다. 예외는 이유·완화책·담당자·재검토 날짜를 기록합니다. 이 기한은 OWASP가 일률적으로 정한 의무가 아닙니다.
