# 적용 범위와 공통 기준

[보안 목차](../../SECURITY.md) · [검증 절차·이력](verification.md)

처음 보안 작업을 시작하거나 서비스 구조·자료 흐름·보호 대상을 바꿀 때 읽습니다.

## 기준 버전과 검증 범위

기준 확인일: **2026-09-29**. 이 날짜의 최신 안정판은 **OWASP ASVS 5.0.0**이며, 2025-05-30에 공개됐습니다. 문서와 요구사항 번호는 [공식 안정판 `v5.0.0_release`](https://github.com/OWASP/ASVS/releases/tag/v5.0.0_release)에 고정합니다. GitHub의 `latest` 릴리스는 개발 중인 Bleeding Edge이므로 안정판 기준으로 사용하지 않습니다.

최초 구현 점검의 기준은 **[v260929.02](https://github.com/YoungsikMoon/buildbrief/releases/tag/260929.02), 커밋 `1c3556d`**입니다. 이후 변경의 확인 범위는 [검증 이력](verification.md#검증-이력)에 기록합니다. 각 모듈의 점검표는 빌드브리프의 위험과 동작에 맞게 묶은 기준이며, ASVS 전체 요구사항의 검사 결과나 인증이 아닙니다. `v5.0.0-1.2.1`처럼 버전이 붙은 번호는 원문을 찾아보기 위한 참조입니다. 한 행의 확인 결과가 참조한 요구사항 전체 충족을 뜻하지는 않습니다.

## 점검 상태

| 상태 | 의미 |
| --- | --- |
| 확인 | 기재한 동작을 코드·자동 검사·수동 확인 중 명시한 방법으로 확인했습니다. 검사하지 않은 경로까지 보장하지 않습니다. |
| 부분 | 방어의 일부는 있지만 미구현 사항이나 추가 검증이 남았습니다. |
| 미점검 | 실제 설정·동작을 확인하지 않았습니다. 안전하다고 간주하지 않습니다. |
| 현재 미해당 | 해당 처리 기능이 없습니다. 재검토 조건이 생기면 검사해야 합니다. |

L1을 출발점으로 삼되 자료와 위험에 따라 L2·L3 항목도 검토합니다. 현재 서비스가 특정 레벨을 충족한다고 선언하지 않습니다. 적용되지 않는 항목에도 이유와 재검토 조건을 남기고, 새 기능이 그 조건을 충족하면 출시 전에 검토를 다시 엽니다.

## 보호할 것과 신뢰 경계

- **이용자 자료:** 아이디어, 답변, 메모, 참고 URL, 프로젝트 백업. 아이디어 자체가 영업상 비밀일 수 있으므로 단순히 “개인정보가 없다”는 이유로 비민감 자료라고 단정하지 않습니다.
- **실행 코드와 배포 권한:** 공개 소스, GitHub Actions, Cloudflare Pages, 도메인·DNS, 운영자 계정. 배포 권한을 탈취하면 악성 JavaScript로 브라우저의 답변을 읽을 수 있으므로 정적 사이트에도 운영 계정 보호가 필요합니다.
- **데이터 흐름:** 직접 입력 → 브라우저 저장 → 기획 초안·Markdown·JSON·클립보드. 가져온 JSON과 기존 localStorage는 정규화 검증 후 사용합니다. 직접 입력의 저장 경로와 가져오기 경로의 검증 차이는 [입력·출력·백업](input-output.md)의 BB-01에 남겼습니다. 이 입력들은 모두 신뢰하지 않습니다. 외부 AI에 붙여 넣기와 백업 공유는 이용자가 직접 하는 별도 전달입니다.
- **현재 없는 기능:** 앱 서버 API, 사용자 로그인·세션, DB, 서버 파일 업로드, URL 수집, AI API 호출, WebRTC. 질문지에서 이런 기능을 선택하는 것은 이용자의 아이디어를 기록하는 것이며 빌드브리프에 그 기능이 구현됐다는 뜻이 아닙니다.

브라우저 저장과 백업은 **평문**입니다. 같은 브라우저 프로필을 쓰는 사람과 해당 출처에서 실행되는 스크립트로부터 내용을 격리하지 않습니다. 프로젝트 UUID·프로젝트 전환은 자료 구분 기능이며 인증·권한 제어가 아닙니다. 실제 비밀번호·API 키·고객 개인정보를 입력하지 않도록 안내하되, 안내만으로 민감한 자료 보호를 충족했다고 판단하지 않습니다.

## ASVS 17개 장의 적용 범위

아래는 **검토할 범위**입니다. 적용 대상이라는 표시는 검사 완료를 뜻하지 않습니다. 원문은 [5.0.0 장별 문서](https://github.com/OWASP/ASVS/tree/v5.0.0_release/5.0/en)에서 확인합니다.

| 장 | 현재 적용 범위와 다시 검토할 조건 |
| --- | --- |
| V1 인코딩·정화 | 적용: HTML·속성·Markdown 출력, JSON 읽기. SQL·OS 명령·XML·템플릿 실행을 추가하면 해당 주입 공격도 검토합니다. |
| V2 입력 검증·업무 규칙 | 적용: 입력 형식, 백업, 길이·행 수 제한, 실패 시 자료 보존. 질문을 건너뛰는 것은 의도한 기능입니다. 결제·예약 등을 실제 제공하면 순서 우회·중복 실행·자동화 악용을 검토합니다. |
| V3 웹 프런트엔드 | 적용: DOM, CSP, 보안 헤더, 출처 경계, 외부 링크. 쿠키·팝업·외부 리소스·`postMessage`를 추가하면 관련 조건을 검토합니다. |
| V4 API·웹 서비스 | 현재 미해당: 앱 API·GraphQL·WebSocket 없음. 추가 시 요청 크기·메서드·콘텐츠 형식·CORS·오류·권한·호출 제한을 검토합니다. |
| V5 파일 처리 | 일부 적용: 이용자가 선택한 JSON 백업 읽기와 파일 내려받기. 서버 업로드·압축 해제·이미지 처리·파일 제공을 추가하면 나머지 범위를 검토합니다. |
| V6 인증 | 앱에는 현재 미해당: 로그인 없음. 운영자 GitHub·Cloudflare 계정은 별도 운영 점검 대상입니다. 앱 로그인 추가 시 가입·인증·복구·MFA를 검토합니다. |
| V7 세션 관리 | 현재 미해당: 앱 세션 없음. 로그인·익명 서버 세션 추가 시 생성·갱신·만료·폐기·동시 세션을 검토합니다. localStorage 답변은 로그인 세션이 아닙니다. |
| V8 권한 제어 | 앱의 다중 사용자 접근 통제에는 현재 미해당: 서버 자료 공유 없음. 서버 저장·공유 링크·관리자 기능 추가 시 매 요청의 소유권·역할·조직 경계를 검토합니다. 배포 권한은 지금도 운영 점검 대상입니다. |
| V9 자체 정보를 담은 토큰 | 현재 미해당: JWT 등 없음. JWT·서명된 공유 토큰 도입 시 서명·알고리즘·발급자·대상·만료·폐기를 검토합니다. 프로젝트 UUID는 접근 토큰이 아닙니다. |
| V10 OAuth·OIDC | 현재 미해당: 소셜 로그인·OAuth 클라이언트 없음. 도입 시 제공자별 공식 흐름과 클라이언트·서버 역할을 구분해 검토합니다. |
| V11 암호 기술 | 일부 적용: 프로젝트 ID 생성에 브라우저의 난수 기능 사용. 자료 암호화는 미구현입니다. 암호화·서명·비밀번호·비밀 토큰 도입 시 알고리즘·키 수명·복구를 검토합니다. UUID 생성으로 비밀 토큰 요건을 충족했다고 보지 않습니다. |
| V12 안전한 통신 | 적용: 공개 사이트 HTTPS·TLS·HSTS. 서버 간 통신은 현재 없으며 추가 시 상대 인증·인증서·암호 설정도 검토합니다. |
| V13 설정 | 적용: 공개 파일, 배포 설정, 운영 비밀값. 서버 통신 추가 시 서비스 계정·송신 목적지 제한을 검토합니다. |
| V14 자료 보호 | 적용: 평문 저장·백업·복사·공유, 자료 분류와 삭제, 호스팅 로그. 서버에 저장하지 않는다는 사실만으로 기밀성 검토를 끝내지 않습니다. |
| V15 안전한 코드·구조 | 적용: 빌드 의존성·권한, 자원 고갈, 형식 혼동·프로토타입 오염, 동시 편집. 외부 라이브러리·백엔드 추가 시 범위를 넓힙니다. |
| V16 보안 로그·오류 | 적용: 브라우저 오류와 저장 실패, 배포·계정 변경 기록·대응. 이용자의 답변 본문을 보안 로그로 수집하지 않습니다. |
| V17 WebRTC | 현재 미해당: 음성·영상·P2P 통신 없음. 추가 시 TURN, 미디어 암호화, 연결 협상과 상대 인증을 검토합니다. |

새 기능의 출시 전 검토는 [기능 확장](feature-changes.md), 운영 계정은 [운영 점검표](operations.md)를 확인합니다.
