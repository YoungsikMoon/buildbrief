# 기능 확장 시 재검토

[보안 목차](../../SECURITY.md) · [적용 범위·상태 기준](scope.md) · [검증 절차·이력](verification.md)

현재 없던 서버 기능·로그인·공유·외부 요청·암호화·AI 연동을 설계할 때 읽습니다. 이 문서는 새 기능의 검토 조건을 관리하며, 현재 구현의 확인 상태를 기록하는 점검표가 아닙니다.

다음 표는 구현 전 확인할 출발점입니다. 새 기능의 관련 ASVS 장 전체를 읽고 범위와 검증 항목을 보완합니다. 현재의 클라이언트 검증을 서버의 접근 통제로 재사용하지 않습니다.

| 추가 기능 | 출시 전에 정의·검증할 내용 | 관련 장 |
| --- | --- | --- |
| URL 미리보기·크롤링·웹훅 | 허용할 목적지·스킴·포트, DNS의 IPv4/IPv6 결과와 실제 연결 대상, 루프백·사설·링크 로컬·메타데이터 접근 차단. 리다이렉트는 기본 금지하고 필요한 경우 매 목적지를 재검증. DNS 재바인딩, 송신 제한, 응답 크기·시간·동시 요청 제한 검증. | V1, V4, V12, V13, V15 |
| 로그인·소셜 로그인·세션 | 가입·로그인·계정 복구의 악용과 계정 존재 노출, 비밀번호 해싱, MFA, 시도 제한. OAuth/OIDC의 PKCE·리다이렉트·state/nonce 등 해당 흐름의 요구사항 검증. 세션 갱신·만료·로그아웃과 쿠키의 Secure·HttpOnly·SameSite, 필요한 CSRF 방어. JWT를 쓴다면 별도 토큰 검증. | V3, V6~V11, V16 |
| 서버 저장·공유·관리자 화면 | 서버 측 입력 검증, 기본 거부, 요청별 사용자·프로젝트·조직 소유권 검사. ID를 바꾼 조회·수정·삭제와 공유 링크 만료·취소 시험. 화면 숨김·CORS·추측 어려운 ID를 권한 검사로 대체하지 않음. | V2, V4, V8, V13~V16 |
| DB·검색·예약·결제 | 매개변수화 쿼리, 최소 DB 권한, 요청 형식·메서드·크기·호출 제한. 중복 요청·동시 처리·업무 순서 우회·금액 변조 검증, 결제 웹훅의 발신 검증과 재전송 처리. 비밀값·오류·거래 로그 보호. | V1, V2, V4, V8, V11~V16 |
| 서버 파일·리치 텍스트·첨부 | 확장자·실제 내용·크기·압축 해제 한도·파일명·저장 경로·접근 권한·실행 방지. 필요에 맞는 악성 파일 검사·HTML/SVG 정화·격리와 안전한 내려받기. 파일 형식 선언만 믿지 않음. | V1, V3, V5, V8, V15 |
| 암호화·민감한 자료 | 자료 분류와 보관·삭제·백업 요구사항, 검증된 암호 라이브러리, 키의 생성·보관·회전·복구·폐기. 브라우저의 암호문과 복호화 키를 함께 두는 것만으로 기밀성 보장이라고 설명하지 않음. 암호화는 XSS·권한 검사의 대체 수단이 아님. | V11~V14 |
| 외부 분석·AI API·도구 실행 | 전달 자료·동의·보관 조건, 서버의 비밀값, 호출·비용 제한과 오류 처리. 문서·URL·모델 출력은 신뢰하지 않고 도구 권한 제한, 외부 전송·삭제·결제 등 중요한 동작은 별도 승인 검증. 프롬프트 문구만으로 주입 공격을 막았다고 보지 않음. AI 전용 위협 검토도 추가. | V1~V4, V8, V13~V16 |

## 적용 범위 갱신

관련 [ASVS 장과 신뢰 경계](scope.md)를 갱신하고, 실제 구현에 적용할 점검 항목을 담당 모듈에 추가합니다. 검증 전에는 확인 상태로 표시하지 않습니다. 작업 결과와 남은 위험은 [검증 이력](verification.md#검증-이력)에 기록합니다.

- 브라우저 입력·출력·파일 검증: [입력·출력·백업](input-output.md)
- 보관·공유·통신과 기밀성: [브라우저·통신·자료 보호](browser-data.md)
- 실행 코드·의존성·배포 권한: [코드·배포](code-and-delivery.md)
- 계정·호스팅 설정과 대응 절차: [운영](operations.md)

새 기능의 분량과 변경 책임이 기존 모듈과 크게 달라질 때만 별도 문서를 만들고, [보안 목차](../../SECURITY.md)에 읽을 조건과 항목 범위를 추가합니다.
