# 개발 준비 템플릿

[프로젝트 문서 목차](../../README.md)

빌드브리프의 아이디어 초안을 외부 AI와 요구사항·설계·개발 계획으로 발전시키기 위한 템플릿입니다. 초보자가 전문 용어를 모두 선택하기보다, AI가 프로젝트에 필요한 결정을 찾아 이유와 확인 방법을 설명하게 합니다.

요청문은 **검토용 초안**이며, 웹앱의 **기획 초안 → AI에 전달할 프롬프트 보기**에서 기본·고급 모드로 선택하고 수정·복사합니다. 기본 템플릿 버전은 **2026-10-01.1**, 공식 기준 확인일은 **2026-09-30**입니다. 통합·브라우저 검증 범위는 아래 변경 이력에 기록합니다. 표준 인증 서식이나 적합성 인증을 제공하지 않습니다.

## 지금 사용하는 방법

1. **‘기획 초안 보기’ → ‘AI에 전달할 프롬프트 보기’**를 누릅니다. 프롬프트 창에서 내용 확인·모드 선택·복사를 모두 처리합니다.
2. **기본/고급 토글**로 요청 범위를 정합니다. 기본은 기획 정리와 빠진 질문을, 고급은 설계·보안·검증 계획과 공식 지침까지 요청합니다. 토글 옆 **?**에서 요청 범위·장점·고려할 점을 비교합니다. 새 프로젝트는 기본 모드입니다.
3. 필요한 부분을 **프롬프트 본문에서 바로 수정**합니다. 기본·고급 수정본은 프로젝트별로 따로 자동 저장하며 모드 전환·새로고침 후에도 유지합니다. **‘복원하기’**를 누르면 확인 후 현재 모드만 현재 답변과 원래 템플릿으로 다시 만듭니다. 별도 메모는 06 마무리 메모에 적습니다.
4. 창 안의 **‘프롬프트 복사’**를 누르고 원하는 AI 대화에 붙여 넣습니다. 복사가 허용되지 않으면 같은 요청문을 Markdown 파일로 내려받습니다. 전체 본문이 비어 있으면 복사 버튼을 비활성화합니다. 비밀번호·API 키·실제 고객 개인정보는 포함하지 않습니다.
5. AI가 먼저 제시한 요구사항 초안과 중요한 확인 질문을 검토하고, 확인한 범위부터 설계와 작업 계획으로 구체화합니다. 이 요청문 자체는 코드 작성이나 배포를 지시하지 않습니다.

일반 **기획 초안 Markdown 내려받기**에는 템플릿을 넣지 않습니다. 기본·고급 AI 프롬프트는 기존 기획 지침과 공통 지침 뒤에 기획 전체를 JSON 코드 블록으로 담고, 고급에는 개발 준비 요청 원문을 추가합니다. AI 답변 형식까지 JSON으로 제한하지 않습니다. 템플릿은 앱과 함께 제공되며 브라우저가 AI 서비스를 자동 호출하지 않습니다.

JSON의 `questions`는 질문·답변·이유·현재/이전 구분을 보존하고 `roles`, `features`, `screens`를 연결합니다. `screens[].canvas`는 기준 높이와 확장된 전체 높이, `elements[].bbox`는 화면 원점 기준 `[x1,y1,x2,y2]`입니다. 부모·레벨·기록 순서·원본 화면 ID·설명·필드·동작을 포함하며 가려진 요소와 편집 필터로 숨긴 요소도 빠지지 않습니다. 공통 요소는 각 화면에 적용한 최종 목록으로 제공합니다. 레벨은 같은 부모 안의 겹침 순서이며 포함 관계는 `parentId`가 결정합니다. JSON은 AI 전달용 `buildbrief-planning` 1형식이며 복원용 프로젝트 백업을 대체하지 않습니다.

사용자의 답변은 사실·희망·선택 이유이고, 템플릿은 AI에 맡길 작업입니다. 템플릿 문구를 사용자의 요구사항이나 `open_questions` 답변에 섞어 저장하지 않습니다.

## 개발 프로젝트에 남길 지침

두 모드 모두 `AGENTS.md → ROOT.md → 현재 작업 → 관련 기획·화면·결정·검증 기록` 흐름을 요청합니다. 원본 JSON, 현재 기획, 화면별 JSON, 결정 기록, 작업별 인계 문서를 나누고 기존 동등 문서를 재사용합니다. 원형 파일의 `.template`는 실제 사용할 프로젝트에 적용할 때 제거합니다. 이 저장소에서는 생성용 예시이며 빌드브리프 자체의 루트 지침으로 설치한 것이 아닙니다.

`AGENTS.md`는 짧은 진입 지시, `ROOT.md`는 읽을 조건·URL·적용·검증의 목차를 담당합니다. 실제 프로젝트에서 확인한 문서 경로·기술 버전·명령을 연결하고 불필요한 후보는 제외 이유와 함께 정리합니다. 기존 지침이 있으면 보존하며 같은 역할의 문서를 재사용합니다. 원형 복사만으로 프로젝트 설정을 끝냈다고 하지 않습니다.

Codex가 기본적으로 인식하는 이름은 `AGENTS.md`이며 `AGENT.md`가 아닙니다. `ROOT.md`는 프로젝트가 정한 이름이므로 진입 지침에서 명시적으로 읽게 합니다. 다른 AI 도구는 해당 도구의 지침 파일 지원을 확인하거나 이 읽기 순서를 직접 전달해야 합니다. [OpenAI 공식 안내](https://learn.chatgpt.com/docs/agent-configuration/agents-md)

프롬프트에는 기획 문서 저장 요청도 포함됩니다. 지정하거나 연결된 쓰기 가능한 프로젝트가 있는 AI는 문서를 생성·갱신하고, 일반 채팅처럼 파일 도구가 없으면 경로별 파일 내용을 제공합니다. 제품 코드·설정 변경과 배포는 별도 요청이 필요합니다. 다른 AI의 기록은 프로젝트 문서로 공유하되 도구별 자동 읽기와 동시 파일 잠금을 보장하지 않습니다. 담당·수정 범위·브랜치 분리와 통합 검증 규칙을 함께 전달합니다.

## 구성 원칙

- 기본 템플릿 하나 안에 요구사항, 진행 절차, 설계, 데이터·보안, 변경 관리, 검증·운영을 담습니다. 처음부터 여러 표준 중 하나를 선택하게 하지 않습니다.
- 공통으로 확인할 항목과 기능이 있을 때만 검토할 항목을 구분합니다. 적용 제외에도 이유를 남기며 정보가 없다는 이유로 제외하지 않습니다.
- 단계별 검토는 하되 변경을 금지하지 않습니다. 변경 시 영향받는 요구사항·설계·시험을 함께 갱신합니다.
- 기술명보다 해결할 문제를 먼저 설명합니다. 구조·기술 추천에는 더 단순한 대안과 도입 비용을 함께 적습니다.
- 문서 분량과 체크 수를 품질로 취급하지 않습니다. 사용자가 이해할 수 있는 설명, 입력과 산출물의 연결, 실제 검증 근거로 평가합니다.

## 웹앱의 저장과 적용

마지막 단계에는 마무리 메모만 제공합니다. 기본/고급 선택, 설명, 전체 프롬프트의 직접 편집·복원·복사는 초안 화면에서 여는 네이티브 대화상자 하나로 모읍니다.

- 템플릿의 선택 여부·내용·적용 버전을 프로젝트별로 저장하고 JSON 백업에 포함합니다. 저장한 버전과 수정 문구는 기본 템플릿이 갱신되어도 자동으로 바꾸지 않습니다. 템플릿 기록이 없는 기존 프로젝트·백업은 선택하지 않은 상태로 열립니다.
- 전체 수정본은 `promptDrafts`의 `basic`·`advanced` 문자열로 나누어 저장·백업합니다. 각 상한은 1,000,000자이며 빈 문자열도 사용자 수정으로 보존합니다. 기본 모드는 기본 수정본 또는 기본 생성문을, 고급 모드는 고급 수정본 또는 고급 생성문을 보여 줍니다. 이전 고급 추가 요청의 수정 내용도 계속 반영합니다.
- **‘복원하기’**는 현재 모드의 수정본을 교체할지 확인한 뒤 현재 답변으로 다시 생성합니다. 고급 모드에서는 추가 템플릿의 내용·버전도 현재 원문으로 복원합니다. 다른 모드의 수정본, 질문 답변과 마무리 메모는 유지합니다. 수정본을 답변 변경으로 자동 덮어쓰지 않으며 UI에서 복원으로 반영하도록 안내합니다.
- 자동 생성한 고급 전달문에서는 추가 요청을 **‘AI에게 함께 요청할 내용’** 구역에 넣고 그 뒤에 사용자 기획 자료를 붙입니다. 사용자가 전체 본문을 수정할 수 있으며 화면의 본문·클립보드·복사 실패 시 내려받는 파일은 같은 내용을 사용합니다. 프롬프트 편집은 질문 답변이나 일반 기획 초안 Markdown을 변경하지 않습니다.
- 선택 체크는 AI에게 부탁한다는 뜻입니다. 시험 통과나 개발 준비 완료로 표시하거나 질문 진행률에 포함하지 않습니다.
- 기존 보고서의 화면·요소 소속, 포함 관계, 역할과 권한, 미정 답변 보존 지침을 유지합니다. 기존 백업도 보존합니다.
- 보안 점검과 과잉 설계 방지는 공통 품질 원칙입니다. 추가 템플릿을 끄더라도 위험한 구현을 허용하는 의미가 되어서는 안 됩니다.

## 갱신 방법

변경 전 [참고 기준](sources.md)의 관련 공식 페이지를 확인합니다. 본문에서 확인하지 못한 조항을 추가하지 않습니다. 요청문을 바꾼 뒤 [검수 기준](review-checklist.md)의 적용 사례로 결과를 비교합니다. 변경 날짜·근거·검토 범위는 아래에 남기며 실제 변경 이력은 Git으로 관리합니다.

고급 원본은 [request-template.md](request-template.md), 두 모드의 공통 원본은 [common-instructions.md](common-instructions.md)입니다. 내용을 바꾸면 [생성 스크립트](../../scripts/planning-template.cjs)의 명시적 버전도 갱신하고 저장소 루트에서 다음 명령을 실행합니다.

```sh
node scripts/planning-template.cjs
node scripts/planning-template.cjs --check
```

첫 명령은 줄바꿈을 LF로 맞추고 앞뒤 공백을 제거한 원문을 [dist/planning-template.js](../../dist/planning-template.js)에 생성합니다. 두 번째 명령은 생성 파일이 원본·버전과 다르면 실패합니다. 생성 파일의 Git 줄바꿈 변환은 허용하며 직접 본문을 수정하지 않습니다. 자산 해시와 관련 검증은 [개발 안내](../development.md)를 따릅니다. 새 기본 버전 배포는 기존 프로젝트에 저장한 요청문을 자동 교체하지 않습니다.
