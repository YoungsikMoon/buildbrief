# 저장과 백업

[프로젝트 안내·문서 목차](../README.md) · [사용 가이드](user-guide.md)

답변이 어디에 남는지, 백업·복구와 다른 기기에서 이어 쓰는 방법, 저장 형식의 호환성을 확인할 때 읽습니다.

답변은 서버에 전송하지 않고 **현재 브라우저의 localStorage**에 자동 저장합니다. 같은 기기·브라우저·프로필·사이트 주소에서 다시 열면 이어서 작성할 수 있습니다. 일반 모드에서 정상 저장되었다면 새로고침이나 PC 재부팅만으로 지워지지는 않습니다.

- ‘이 브라우저에 저장됨’을 누르면 저장 상태와 보관·복구 방법을 확인할 수 있습니다.
- ‘백업 내려받기’는 현재 프로젝트를, ‘관리’의 ‘전체 프로젝트 백업’은 모든 프로젝트를 JSON 파일로 내려받습니다.
- ‘백업 불러오기’는 파일을 검증한 뒤 새 프로젝트로 추가합니다. 현재 프로젝트를 덮어쓰지 않습니다.
- 저장 실패, 기존 자료 읽기 실패, 다른 탭의 변경을 감지하면 안내합니다. 다른 탭 변경을 감지한 경우 자동 저장을 멈춥니다. 현재 입력은 백업한 뒤 저장 안내를 따라 복구할 수 있습니다. 여러 탭이 거의 동시에 저장하는 경우까지 보호하는 것은 아니므로 같은 프로젝트의 동시 편집은 피하세요.

사이트 데이터 삭제, 시크릿 모드 종료, 브라우저 초기화, 기기 고장 등에 대비해 중요한 기록은 파일로 백업하세요. 다른 브라우저·기기·사이트 주소로 자동 동기화되지 않습니다. 브라우저 저장과 백업 파일을 별도로 암호화하지 않으므로 실제 비밀번호나 API 키를 입력하지 마세요. 외부 AI에 초안을 붙여 넣는 경우에는 전달할 내용을 직접 확인하세요.

현재 저장 키는 `buildbrief.ideas.v1`이며 백업 형식은 단일 프로젝트 `buildbrief-idea`, 전체 프로젝트 `buildbrief-ideas`입니다. 이전 기술 설계 질문지의 저장 키는 삭제하지 않지만, 이전 모델의 답변·백업을 현재 아이디어 기획 모델로 자동 변환하지는 않습니다.

마지막 단계를 마무리 메모로 바꾼 뒤에도 기존 `open_questions` 답변과 이유는 그대로 이어집니다. 제거한 질문의 `scope`·`excluded_work`·`success_check` 답변·작성 중 내용·이유·추천 요청은 검증 후 저장과 백업에 보관합니다. 기존 답변과 이유는 초안의 ‘이전에 작성한 내용’에서 확인하며, 작성 화면이나 진행률에 다시 추가하지 않습니다. 이전 추천 요청은 백업에 남지만 현재 추천 요청 목록으로 되살리지 않습니다.

화면별 `elementOptions`에는 입력 방식·목록 탐색 방식, `customElements`에는 직접 추가한 요소의 식별자·이름·용도를 보관합니다. 이 필드가 없는 기존 아이디어 기획 백업도 불러올 수 있으며 기존 화면 요소와 용도 메모는 유지됩니다. 선택을 해제한 기본 요소의 메모·세부 선택도 백업에 보관합니다.

보호 수준과 남은 보안 점검은 [브라우저·자료 보호](security/browser-data.md), 가져오기·동시 편집의 구현 한계는 [입력·출력·백업 점검표](security/input-output.md)를 확인하세요.

현재 6단계 목차는 `navigationVersion: 3`으로 구분합니다. 이전 8단계(`2`)와 9단계(값 없음)의 위치를 각각 한 번만 변환합니다. 이용 과정은 화면·기능으로, 로그인·권한은 사용자·환경으로 이동합니다. 답변 ID, 저장 키와 백업 버전은 바꾸지 않습니다.

화면별 `elementContents`에는 폼 항목·표의 열·목록 표시 정보, 연결 기능, 요소별 추천 요청과 이유를 보관합니다. 모든 기본 요소와 직접 추가한 요소, 화면 전체에 `flow`(동작 목록)와 `recommendFlow`를 저장합니다. 각 동작은 고유 ID와 행동·실행 기능 ID·다음 화면 ID·처리 결과를 가집니다. 다음 화면의 `@stay`와 `@back`은 현재 화면 유지·뒤로 가기를 뜻합니다. 역할 목록의 기존 ID를 유지하고 화면의 `roleIds`로 연결합니다. 역할 이름 변경은 연결을 바꾸지 않으며, 삭제된 연결은 검토 대상으로 표시합니다. 기존 자유 입력 이용 대상을 특정 역할로 임의 변환하지 않습니다. 새 필드가 없는 백업에는 빈 값만 보완합니다. 요소 선택 해제 시 세부 기록은 보존하고 현재 초안에서 제외합니다.

예전 ‘일부 기능에서만 로그인’·‘주요 기능은 로그인 후 사용’은 ‘로그인 필요’로 표시하되 원문을 `login_scope_history`에 보존합니다. 이전 이용 과정·완료/실패 경험·가입 정보·계정 관리 답변과 이유는 초안의 ‘이전에 작성한 내용’과 백업에 남깁니다. 새 화면 동작으로 임의 분배하거나 모든 화면을 로그인 필수로 바꾸지 않습니다. 로그인 없이 사용을 골라 숨겨진 로그인 방식도 저장·백업에는 유지하고 현재 초안에서는 제외합니다.

새 선택지에서 일괄 제공하던 ‘아직 미정’은 제거했습니다. 이전에 저장한 단일·복수 선택과 기능 우선순위의 같은 값은 입력 검증·백업·선택 상태에 그대로 보존합니다. 새 기능의 우선순위는 빈칸으로 시작합니다. 빈 세부 항목을 초안에서 생략하는 것은 저장된 답변을 삭제하거나 기본값을 확정하는 처리가 아닙니다.
