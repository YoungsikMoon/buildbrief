# UI와 접근성 기준

[프로젝트 안내·문서 목차](../README.md) · [사용 가이드](user-guide.md)

안내 화면·질문·기획 초안·프로젝트 관리의 색상·글자 크기·접근성을 바꿀 때 읽습니다. 관련 코드: [styles.css](../dist/styles.css), [index.html](../dist/index.html), [views.js](../dist/views.js), [app.js](../dist/app.js).

## 시작 안내의 구성 원칙

안내 화면은 [NN/g의 홈페이지 사용성 원칙](https://www.nngroup.com/articles/top-ten-guidelines-for-homepage-usability/) 중 명확한 목적, 주요 행동, 구체적인 결과물 예시를 기준으로 구성했습니다. 글자 대비와 클릭 영역은 [WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/)를 참고했습니다. 전환율 개선은 별도의 사용자 관찰과 측정으로 확인해야 합니다.

첫 영역은 소개와 시작 버튼을 가운데 모으고, 그 아래 핵심 장점 네 가지를 배치합니다. 소개 아래의 BEFORE → AFTER 영역은 산책 모임·공방 예약·재료로 요리 찾기의 세 가지 가상 예시를 보여 줍니다. 각 카드에서 한 줄 아이디어 → 구체화한 서비스 화면 → 문제·사용자·첫 기능·선택 이유 순서로 읽습니다. 화면 이미지는 개발 중에 만든 정적인 예시이며 실제 출시 사례나 사이트의 자동 생성 결과를 뜻하지 않습니다. 상세 사용법은 기존 펼침 가이드에 둡니다.

예시는 브라우저 기본 가로 스크롤과 CSS scroll snap으로 넘깁니다. 가운데 카드는 선명하게, 옆 카드는 일부만 흐릿하게 노출하고, 위쪽에 이전·다음 버튼과 현재 위치를 표시합니다. 터치·트랙패드·좌우 방향키·Home/End로도 이동하며 자동 재생하지 않습니다. 동작 줄이기 설정에서는 버튼 이동의 애니메이션을 생략합니다. 예시에는 사용자의 답변을 넣거나 저장하지 않습니다.

예시의 시각적 우선순위는 영역 제목 → 서비스 이름 → 기획 내용 → 항목 이름·BEFORE/AFTER 표시 순서입니다. 본문 크기는 유지하고, PC의 넓은 카드에서는 이미지와 기획 요약을 나란히 배치해 높이를 줄입니다. 카드 너비가 40rem 이하이면 세로로 배치하고 이미지 폭을 460px 이하로 제한합니다. 20rem 이하에서는 항목 이름도 본문 위로 이동해 작은 화면과 글자 확대에 대응합니다. 반복되는 배지·색상 칩은 줄이고 선택 이유는 얇은 구분선 아래에 배치합니다. 탐색 버튼은 영역 제목 옆에 두며 44px 누름 영역을 유지합니다. 기존 생성 이미지는 그대로 사용하며 저장·통신·보안 동작을 변경하지 않습니다.

서비스 화면 세 장은 OpenAI 내장 이미지 생성으로 제작했습니다. [생성 프롬프트](idea-example-image-prompts.json)와 [공개 이미지](../dist/idea-examples/)를 분리하고, 공개 파일은 1200×800 WebP·각 250KB 이하로 제한합니다. 대체 텍스트와 카드의 기획 내용으로 화면의 의미를 설명합니다. PC·모바일 배치, 200% 글자 확대, 키보드와 터치 이동은 [브라우저 검사](../scripts/check-guide-browser.cjs)로 확인합니다.

개인정보 관련 장점은 ‘회원가입 없이 시작’, ‘작성 내용은 이 브라우저에 저장’, ‘서버·외부 AI로 자동 전송하지 않음’처럼 실제 동작으로 한정합니다. ‘아이디어 유출 없음’이나 암호화 보관을 보장하지 않습니다. 외부 AI에 직접 전달하는 흐름과 브라우저 보관의 경계는 FAQ와 [자료 보호 기준](security/browser-data.md)을 따릅니다. 이번 안내 개편은 저장·통신·보안 구현을 바꾸지 않습니다.

## 색상과 글자 크기

화면 전체에 짙은 잉크색 제목, 어두운 회색 본문, 딥 블루 버튼·선택 상태와 흰색 입력 영역을 사용합니다. 보조 설명도 읽기 쉬운 대비를 유지하고, 입력창 테두리와 키보드 포커스를 구분합니다.

PC 본문은 과도하게 크게 느껴진다는 피드백에 따라 19px에서 16px로 조정했습니다. 제목·메뉴·보조 글자도 아래 표에 맞춰 줄였으며, 모바일 크기와 버튼의 누르는 영역은 유지합니다. 모바일은 앞선 피드백에 따라 이전 크기의 75%(200→150 비율)로 줄인 상태입니다. 기본 화면에 200% 확대를 적용했던 것은 아니며, 아래의 확대 검증 기준과 구분합니다.

아래 수치는 브라우저 기본 글자 크기가 16px일 때이며, 실제 스타일은 `rem`으로 작성해 사용자 글자 크기 설정을 따릅니다. 모바일 기준은 화면 너비 1,000px 이하입니다. 입력창·선택 상자는 최소 `1rem`(기본 16px)을 유지하며 버튼의 누르는 영역과 줄 간격은 유지합니다. 공통 글자 크기 변수로 안내·작성·기획 초안·프로젝트 관리 화면에 같은 기준을 적용합니다.

| 역할 | PC | 모바일 |
| --- | --- | --- |
| 단계·초안 문서 제목 | 28px | 21px |
| 질문 묶음 제목 | 22px | 18px |
| 질문·카드 제목 | 18px | 16.5px |
| 본문·설명·선택지·기획 초안 | 16px | 14.25px |
| 입력창·선택 상자의 입력값 | 16px | 16px |
| 메뉴·버튼·입력란 이름 | 14px | 13.5px |
| 버전·질문 수 등 짧은 보조 정보 | 12px | 12px |

시작 안내의 큰 제목은 PC 40px, 너비 761~1,000px에서는 36px, 760px 이하에서는 24px입니다. 로고 그림과 장식용 화살표의 크기는 글자 배율에 포함하지 않습니다.

글자를 키웠을 때도 읽고 조작할 수 있도록 버튼과 카드의 줄바꿈·간격을 함께 조정합니다. 확대 시 내용이나 기능이 사라지지 않는지는 [WCAG의 텍스트 200% 확대 기준](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)으로 확인합니다.

## 화면 요소 예시

30개 요소는 가상의 수업 예약 서비스 화면을 보여 줍니다. 주황색 테두리로 해당 요소의 위치를 표시하고, 이름과 확대 화면의 대체 텍스트로 의미를 설명합니다. 정적인 예시이므로 토스트가 사라지는 시간이나 서랍이 열리는 동작은 설명을 함께 읽어야 합니다.

- 이미지를 누르면 기존 도움말 대화 상자에서 확대합니다. 선택은 아래 체크박스·이름으로 분리하여 예시를 보다가 답변이 바뀌지 않게 합니다. 키보드로도 열고 닫을 수 있으며, 긴 내용에서도 닫기 버튼이 보이도록 합니다.
- 이미지는 [element-examples](../dist/element-examples/)의 1200×800 WebP이며, 파일당 250KB 이하로 제한합니다. 접힌 묶음의 이미지는 브라우저 지연 로딩을 사용합니다. 원본 크기로 확인하려면 같은 사이트의 이미지 파일을 새 탭에서 엽니다.
- OpenAI 내장 이미지 생성으로 제작했으며 실제 이용자 자료를 사용하지 않았습니다. [30개 생성 프롬프트](ui-element-image-prompts.json)를 남겨 이후 같은 의도로 다시 만들 수 있게 합니다. 생성은 개발 중의 작업이며 사이트 사용·빌드 시 AI 호출은 없습니다.
- 교체할 때에는 요소 구분, 한국어 표기, 표·달력·진행 막대의 일관성을 눈으로 확인하고 PC·모바일 확대 보기와 이미지 경로 검사를 함께 수행합니다.

변경 후 PC·모바일에서 입력, 긴 문구, 버튼 줄바꿈과 목차 스크롤을 함께 확인하세요. 기능별 조작 흐름은 [사용 가이드](user-guide.md), 검증 명령은 [개발 문서](development.md)를 참고하세요.

## 화면·기능 편집의 계층

화면 하나를 가장 큰 카드로 묶고 이름을 강조합니다. 기본 정보 → 요소 선택 → 요소 안의 기능 → 기능별 동작 순서로 편집합니다. 기능 후보 선택과 직접 추가는 같은 크기의 두 버튼으로 나란히 둡니다. 기능을 추가하면 동작 입력이 이어지고, 해당 동작의 오류·예외는 AI 추천 또는 직접 입력으로 정합니다. 폼·표의 상세 항목, 기능 설명·규칙, 화면 전체 설정은 펼침 영역으로 분리합니다. 화면 머리글만 옅은 파랑으로 강조하고, 요소·기능·동작은 제목과 흰색·옅은 회색 배경으로 범위를 나눕니다. 모바일에서는 기본 정보 두 열을 한 열로 바꿉니다.

역할 선택은 네이티브 details·검색 입력·체크박스로 구성합니다. 닫혀 있을 때 선택 요약을 보이고, 열면 이름 검색과 복수 선택을 제공합니다. PC에서는 목록이 떠서 주변 배치를 밀지 않으며 모바일에서는 본문 안에서 펼쳐 작은 화면에 잘리지 않게 합니다. 긴 목록은 별도로 스크롤하고 Escape·바깥 클릭으로 닫습니다. 검색어는 답변에 저장하지 않고 선택한 역할 ID만 보관합니다. 별도 UI 라이브러리는 사용하지 않습니다.

기능 삭제 버튼은 펼침 영역 밖의 머리글에 두어 항상 보입니다. 공유 기능 삭제 전 확인과 화면별 연결 해제는 유지합니다. 새 화면에서는 요소 후보를 먼저 보여 주고, 이후에는 ‘요소 선택·추가’에서 열고, 이미 선택한 요소의 설정은 그 아래에서 편집합니다. 추천 체크박스에는 요청 대상을 짧게 표시하고, 복사·AI 전달 안내는 반복하지 않습니다. 상세 범위는 초안에 명시합니다. 전달 방법은 시작 안내와 기획 초안에서 안내합니다.
