# UI와 접근성 기준

[프로젝트 안내·문서 목차](../README.md) · [사용 가이드](user-guide.md)

안내 화면·질문·기획 초안·프로젝트 관리의 색상·글자 크기·접근성을 바꿀 때 읽습니다. 관련 코드: [styles.css](../dist/styles.css), [index.html](../dist/index.html), [views.js](../dist/views.js), [app.js](../dist/app.js).

## 시작 안내의 구성 원칙

안내 화면은 [NN/g의 홈페이지 사용성 원칙](https://www.nngroup.com/articles/top-ten-guidelines-for-homepage-usability/) 중 명확한 목적, 주요 행동, 구체적인 결과물 예시를 기준으로 구성했습니다. 글자 대비와 클릭 영역은 [WCAG 2.2](https://www.w3.org/WAI/standards-guidelines/wcag/)를 참고했습니다. 전환율 개선은 별도의 사용자 관찰과 측정으로 확인해야 합니다.

첫 영역은 왼쪽에 소개·시작 버튼, 오른쪽에 핵심 장점 네 가지를 배치합니다. 1,200px 이하에서는 한 열로 전환합니다. 반복되는 작은 제목을 생략하고 예시가 첫 화면에서 더 일찍 보이도록 높이를 줄입니다. 소개 아래의 BEFORE → AFTER 영역은 산책 모임·공방 예약·재료로 요리 찾기의 세 가지 가상 예시를 보여 줍니다. 각 카드에서 한 줄 아이디어 → 구체화한 서비스 화면 → 문제·사용자·첫 기능·선택 이유 순서로 읽습니다. 화면 이미지는 개발 중에 만든 정적인 예시이며 실제 출시 사례나 사이트의 자동 생성 결과를 뜻하지 않습니다. 상세 사용법은 기존 펼침 가이드에 둡니다.

예시는 브라우저 기본 가로 스크롤과 CSS scroll snap으로 넘깁니다. 가운데 카드는 선명하게, 옆 카드는 일부만 흐릿하게 노출하고, 위쪽에 이전·다음 버튼과 현재 위치를 표시합니다. 터치·트랙패드·좌우 방향키·Home/End로도 이동하며 자동 재생하지 않습니다. 동작 줄이기 설정에서는 버튼 이동의 애니메이션을 생략합니다. 예시에는 사용자의 답변을 넣거나 저장하지 않습니다.

예시의 시각적 우선순위는 영역 제목 → 서비스 이름 → 기획 내용 → 항목 이름·BEFORE/AFTER 표시 순서입니다. 본문 크기는 유지하고, PC의 넓은 카드에서는 이미지와 기획 요약을 나란히 배치해 높이를 줄입니다. 카드 너비가 40rem 이하이면 세로로 배치하고 이미지 폭을 460px 이하로 제한합니다. 20rem 이하에서는 항목 이름도 본문 위로 이동해 작은 화면과 글자 확대에 대응합니다. 반복되는 배지·색상 칩은 줄이고 선택 이유는 얇은 구분선 아래에 배치합니다. 탐색 버튼은 영역 제목 옆에 두며 44px 누름 영역을 유지합니다. 기존 생성 이미지는 그대로 사용하며 저장·통신·보안 동작을 변경하지 않습니다.

서비스 화면 세 장은 OpenAI 내장 이미지 생성으로 제작했습니다. [생성 프롬프트](idea-example-image-prompts.json)와 [공개 이미지](../dist/idea-examples/)를 분리하고, 공개 파일은 1200×800 WebP·각 250KB 이하로 제한합니다. 대체 텍스트와 카드의 기획 내용으로 화면의 의미를 설명합니다. PC·모바일 배치, 200% 글자 확대, 키보드와 터치 이동은 [브라우저 검사](../scripts/check-guide-browser.cjs)로 확인합니다.

개인정보 관련 장점은 ‘회원가입 없이 시작’, ‘작성 내용은 이 브라우저에 저장’, ‘서버·외부 AI로 자동 전송하지 않음’처럼 실제 동작으로 한정합니다. ‘아이디어 유출 없음’이나 암호화 보관을 보장하지 않습니다. 외부 AI에 직접 전달하는 흐름과 브라우저 보관의 경계는 FAQ와 [자료 보호 기준](security/browser-data.md)을 따릅니다. 이번 안내 개편은 저장·통신·보안 구현을 바꾸지 않습니다.

## 공통 화면 구성

상단은 로고와 버전을 한 줄에 배치하고 기본 높이를 PC 64px·모바일 56px로 줄입니다. 글자 확대 시 내용만큼 늘어나며 실제 높이는 기존 관찰 코드가 반영합니다. PC 메뉴 폭은 260px이고 일반 작성 화면은 최대 1,040px로 읽기 좋은 폭을 유지합니다. 편집기는 남는 폭을 캔버스에 사용합니다. 주요 버튼은 44px 이상, 캔버스 추가·도움말·크기 손잡이는 기존 전용 규격을 유지합니다.

질문 사이 간격은 24px로 정돈하고 패널 설명은 조작 글자 크기에 맞춥니다. 초안은 바깥 문서 영역을 유지하면서 질문마다 둘렀던 중복 테두리를 없애고 구분선·제목으로 구별합니다. 선택, 위험, 저장 상태와 키보드 초점은 기존 의미를 유지합니다.

## 색상과 글자 크기

화면 전체에 짙은 잉크색 제목, 어두운 회색 본문, 딥 블루 버튼·선택 상태와 흰색 입력 영역을 사용합니다. 보조 설명도 읽기 쉬운 대비를 유지하고, 입력창 테두리와 키보드 포커스를 구분합니다.

기존 글꼴과 크기를 고정하는 제한은 두지 않습니다. 작성·편집 화면은 Impeccable의 Operate 기준으로 한국어 가독성, 정보 계층, 일관성과 조작 편의를 평가하고 글꼴·크기·굵기·행간을 조정합니다. 소개 화면은 Taste Skill의 적용 범위도 참고합니다. 스킬의 일반 기본값을 모든 화면에 일괄 적용하지 않습니다.

기본 글꼴은 [Pretendard 1.3.9](https://github.com/orioncactus/pretendard/tree/v1.3.9)입니다. 공식 커밋 `5c41199ea0024a9e0b2cb31735265056e5472d76`의 가변 WOFF2를 수정 없이 자체 제공하며 [OFL 라이선스](../dist/fonts/OFL.txt)를 함께 배포합니다. 파일은 2,057,688바이트이며 한글 사용자 입력의 범위를 임의로 제한하지 않는 전체 글꼴을 사용합니다. 별도 폰트 서버나 CDN 요청은 없습니다. `font-display: swap`과 시스템 대체 글꼴로 로딩 중·실패 시에도 읽고 입력할 수 있고, preload로 요청을 일찍 시작합니다. 글꼴 SHA-256은 `9599f12fd42fc0bce1cd50b47a0c022e108d7aa64dd0d1bb0ed44f3282d900b4`로 검증합니다.

아래 표는 현재 구현 현황이며 앞으로 반드시 유지해야 하는 고정값은 아닙니다. 현재 PC 본문은 16px, 모바일 본문은 15px입니다. 이전 크기 조정 이력과 사용자 확대 검증은 실제 디자인 결정과 구분합니다.

아래 수치는 브라우저 기본 글자 크기가 16px일 때이며, 실제 스타일은 `rem`으로 작성해 사용자 글자 크기 설정을 따릅니다. 모바일 기준은 화면 너비 1,000px 이하입니다. 입력창·선택 상자는 최소 `1rem`(기본 16px)을 유지하며 버튼의 누르는 영역과 줄 간격은 유지합니다. 공통 글자 크기 변수로 안내·작성·기획 초안·프로젝트 관리 화면에 같은 기준을 적용합니다.

새 탭·메뉴는 `--type-control`처럼 용도에 맞는 공통 변수를 사용하며 본문 크기를 그대로 상속하지 않습니다. 크기 체계를 조정할 때는 같은 역할의 구성요소에 일관되게 반영하고 PC·모바일·글자 확대 상태를 확인합니다. [프로젝트 디자인 지침](../AGENTS.md)에 스킬 적용 범위를 기록합니다.

| 역할 | PC | 모바일 |
| --- | --- | --- |
| 단계·초안 문서 제목 | 26px | 24px |
| 질문 묶음 제목 | 20px | 19px |
| 질문·카드 제목 | 18px | 17px |
| 본문·설명·선택지·기획 초안 | 16px | 15px |
| 입력창·선택 상자의 입력값 | 16px | 16px |
| 메뉴·버튼·입력란 이름 | 14px | 14px |
| 버전·질문 수 등 짧은 보조 정보 | 12px | 12px |

시작 안내의 큰 제목은 PC 40px, 너비 761~1,000px에서는 36px, 760px 이하에서는 28px입니다. 로고 그림과 장식용 화살표의 크기는 글자 배율에 포함하지 않습니다.

글자를 키웠을 때도 읽고 조작할 수 있도록 버튼과 카드의 줄바꿈·간격을 함께 조정합니다. 확대 시 내용이나 기능이 사라지지 않는지는 [WCAG의 텍스트 200% 확대 기준](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html)으로 확인합니다.

## 화면 요소 예시

30개 요소는 가상의 수업 예약 서비스 화면을 보여 줍니다. 주황색 테두리로 해당 요소의 위치를 표시하고, 이름과 확대 화면의 대체 텍스트로 의미를 설명합니다. 정적인 예시이므로 토스트가 사라지는 시간이나 서랍이 열리는 동작은 설명을 함께 읽어야 합니다.

- 참고 탭에서 자료를 열고 분류를 선택합니다. 이미지·이름을 누르면 기존 도움말 대화 상자에서 예시를 확대합니다. 반복 안내 문구는 각 카드에 붙이지 않으며, 참고 자료를 보는 동작은 요소를 삽입하거나 답변을 바꾸지 않습니다. 키보드로도 열고 닫을 수 있으며, 긴 내용에서도 닫기 버튼이 보이도록 합니다.
- 이미지는 [element-examples](../dist/element-examples/)의 1200×800 WebP이며, 파일당 250KB 이하로 제한합니다. 목록 이미지는 브라우저 지연 로딩을 사용합니다. 원본 크기로 확인하려면 같은 사이트의 이미지 파일을 새 탭에서 엽니다.
- OpenAI 내장 이미지 생성으로 제작했으며 실제 이용자 자료를 사용하지 않았습니다. [30개 생성 프롬프트](ui-element-image-prompts.json)를 남겨 이후 같은 의도로 다시 만들 수 있게 합니다. 생성은 개발 중의 작업이며 사이트 사용·빌드 시 AI 호출은 없습니다.
- 교체할 때에는 요소 구분, 한국어 표기, 표·달력·진행 막대의 일관성을 눈으로 확인하고 PC·모바일 확대 보기와 이미지 경로 검사를 함께 수행합니다.

변경 후 PC·모바일에서 입력, 긴 문구, 버튼 줄바꿈과 목차 스크롤을 함께 확인하세요. 기능별 조작 흐름은 [사용 가이드](user-guide.md), 검증 명령은 [개발 문서](development.md)를 참고하세요.

## 작성 페이지의 제목과 이동

상단에는 페이지 제목과 짧은 설명을 한 번만 표시합니다. ‘아이디어를 기획으로’ 문구와 첫 단계의 반복 안내 배너는 생략합니다. 질문 묶음이 하나인 페이지에서는 묶음 제목·설명을 다시 표시하지 않고 바로 질문을 보여 줍니다. 여러 주제를 구분해야 하는 페이지는 묶음 제목·설명을 유지합니다.

현재 단계는 다음 단계 버튼 안에 `1 / 6`처럼 표시하고, 마지막 단계는 `기획 초안 보기 6 / 6 →`로 표시합니다. 버튼의 접근성 이름에는 현재 단계와 이동 동작을 함께 알립니다. 작은 화면과 글자 확대에서는 버튼 내용이 줄바꿈되도록 합니다. 프로젝트 관리는 기존 보조 버튼 스타일과 조절 아이콘을 사용하며 키보드 초점·대화 상자 열기 동작을 유지합니다.

## 화면·기능 편집의 계층

6개 구역은 유지하고 내부와 중첩 요소에는 8px 간격의 점 격자를 표시합니다. 요소는 가로 비율·세로 픽셀 좌표로 독립 배치하며 이동·크기 조절로 이웃 요소를 밀지 않습니다. 서로 다른 높이와 겹침을 허용합니다. 선택은 테두리만 강조하고 겹침 순서는 유지합니다. 끌어 놓기와 크기 조절은 8px 단위로 가볍게 맞춥니다. 놓을 위치는 점선으로 표시하고 설정에는 위치 방향 버튼과 절반·전체 너비 버튼을 둡니다. 기존 행·열이나 순서만 있는 박스는 기존 배치를 계산해서 표시하고, 편집 시 보이는 위치를 저장합니다. 공통 요소는 개별 화면에서 위치를 바꾸지 않습니다. 작은 화면에서는 캔버스 내부만 가로로 스크롤하여 구역 폭을 확보합니다.

크게 보기는 편집기를 창 전체로 넓히는 임시 보기 상태입니다. 페이지 메뉴·제목·이동 버튼·바닥글과 화면 목록 추천을 숨기고, 화면 탭과 작게 보기 버튼을 상단에 유지합니다. 선택·편집·화면 전환 중에도 확대 상태를 유지하며 작게 보기 또는 Escape로 돌아와 버튼 초점을 복원합니다. 도움말 대화 상자와 크기 조절 취소를 먼저 처리합니다. 단계·프로젝트 전환·새로고침에서는 일반 보기로 돌아옵니다.

요소 레벨은 `placements.level`에 1~999의 정수로 저장합니다. 구역에 추가한 요소는 1레벨, 요소 안에 추가한 요소는 부모의 현재 레벨로 시작합니다. 이후 부모 레벨 변경이나 요소 추가·삭제가 다른 요소의 레벨을 바꾸지 않습니다. 레벨이 없는 기존 자료는 1로 표시하되 기존 `layoutOrder`를 보존합니다. 같은 부모 안에서는 높은 레벨이 앞에 표시되고, 같은 레벨은 기존 배치 순서를 유지하며 새 요소가 앞에 놓입니다. 자식은 부모 묶음 안에서 겹칩니다. 선택·위치 이동·크기 조절은 레벨을 바꾸지 않습니다.

요소 탭의 숫자 입력으로 직접 지정하거나 ↑·↓로 1씩 조절합니다. Enter 또는 입력칸을 벗어날 때 적용하고, 빈 값·소수·범위 밖 숫자는 저장하지 않고 오류를 알립니다. Escape는 입력값을 복원합니다. ? 도움말에서 기본값과 겹침 기준을 확인할 수 있습니다.

캔버스 상단 오른쪽의 요소 보기 드롭다운은 기본 전체 체크와 레벨 내림차순 목록을 제공합니다. 같은 레벨을 한 항목으로 묶고 요소 수를 표시하며, 부분 선택은 전체 체크박스의 중간 상태로 알립니다. 보기 선택은 화면 ID별 임시 상태입니다. 새 요소를 추가하거나 레벨을 변경하면 해당 레벨의 숨김을 해제해 계속 편집할 수 있습니다. 가린 부모의 내부 요소도 독립적으로 표시하되 배치·높이는 유지하며, 숨긴 요소의 조작 버튼은 키보드와 포인터에서 제외합니다. 드롭다운은 Escape·바깥 클릭으로 닫습니다.

화면·기능 단계는 PC에서 작업 영역의 최대 폭 제한을 풀고, 늘어난 공간을 배치 화면에 할당합니다. 제목과 설명은 나란히 배치하고 화면 제목의 반복 표식을 생략합니다. 화면 아래 남는 높이는 캔버스 본문에 할당하며, 내용이 많으면 자연스럽게 늘어납니다. 설정 패널은 읽기 좋은 폭으로 유지합니다. 글을 읽고 쓰는 나머지 단계는 기존 본문 폭을 유지하며, 모바일에서는 배치 화면 아래에 설정 패널을 둡니다.

위에는 공통·개별 화면 탭, 가운데에는 6개 구역의 배치 화면, 오른쪽에는 설정 패널을 둡니다. 화면 목록 추천 요청은 탭 옆에 배치하고 폭이 좁으면 다음 줄로 보냅니다. 이 단계의 제목·추천 요청·화면 탭 간격은 짧게 유지하고, 같은 안내를 반복하는 별도 도구 줄은 두지 않습니다. 구역의 추가 버튼으로 요소 박스를 만들고 이름과 용도·기능·동작만 입력합니다. 새 화면은 새 화면 1·2…, 직접 추가한 요소는 화면별 요소1·2… 이름을 저장하며 기존 번호·이름과 겹치지 않게 다음 번호를 붙입니다. 빈 이름은 기존 명시적 이름을 피한 번호로 표시하고 원본을 덮어쓰지 않습니다. 캔버스·탭·접근성 이름·초안에 같은 표시 규칙을 적용합니다. 오른쪽 패널은 화면·요소·참고 세 탭으로 구성하고 별도 화면 설정 버튼과 ?/설정으로 버튼은 생략합니다. 화면 전체의 이름·목적·역할은 화면 탭에서, 화면별 선택 이유는 배치 화면 아래에서 적습니다.

참고 탭은 요소·기능 참고 자료를 같은 패널에서 엽니다. 네이티브 선택 상자로 한 분류만 표시하고 이미지·이름으로 목록을 간결하게 구성합니다. 기존 이미지·도움말·세부 방식·기능 설명은 유지합니다. 패널 제목과 분류 선택은 스크롤 중에도 찾을 수 있고, 모바일 참고 목록도 높이를 제한해 페이지가 길게 늘어나지 않게 합니다. 요소 탭으로 돌아오면 원래 선택한 요소를 편집하며 자료 탐색은 답변을 바꾸지 않습니다. PC에서는 열린 패널 헤더 안에 접기 화살표를 두고, 닫힌 상태에서만 왼쪽에 얇은 펼치기 손잡이를 남겨 작업 폭을 확보합니다. 접기·펼치기 버튼은 모바일에서도 문구 없이 화살표만 표시하며 44×44px을 유지합니다. 동작 설명은 접근성 이름과 마우스 도움말로 제공하고 키보드 초점·펼침 상태를 유지합니다. 접었다 열어도 선택한 요소·참고 분류를 바꾸지 않습니다.

배치 화면의 요소에는 이름만 표시합니다. 용도·기능·동작 설명은 요소를 선택한 뒤 설정 패널에서 확인·수정하며, 설명 길이가 박스 크기에 영향을 주지 않게 합니다. PC에서는 오른쪽, 모바일에서는 배치 화면 아래의 기존 패널을 사용합니다. 설명은 초안·백업에 그대로 포함합니다. ‘화면 밖 기능’과 별도 기능 후속 질문은 작성 화면·진행률에서 제외하며, 이전 기록은 기존 보존 경로로 초안·백업에 남깁니다.

공통 요소는 옅은 배경과 ‘공통’ 표식으로 구분합니다. 개별 화면에서 공통 요소 안에 넣은 박스는 해당 화면에만 속합니다. 포함 관계는 중첩된 테두리로 표현하고, 추가는 구역·요소 이름 바로 오른쪽의 + 버튼으로 제공합니다. 별도의 추가 행은 두지 않고, 자식이 없는 요소의 구분선도 생략합니다. + 버튼은 항상 보이며 32px 누름 영역·접근성 이름·키보드 초점을 유지하고 빈 요소에 끌어 놓을 대상으로도 사용합니다. PC 끌어 놓기, 레벨 숫자 입력과 ↑·↓ 조절, 휴지통 삭제를 제공합니다. 크기 손잡이는 24px이며 마우스·터치·방향키를 지원하고 Escape·포인터 취소 시 저장하지 않습니다. 높이는 64px까지 줄이고 기존 800px 상한은 두지 않으며, 내용·중첩 요소가 요구하는 높이는 확보합니다. 높이는 안전한 정수, 너비는 1~100의 유한한 숫자(소수 포함)만 허용하며 자유 CSS를 받지 않습니다. 상위 요소 삭제 시 자식은 밖으로 옮깁니다.

역할 선택은 네이티브 details·검색 입력·체크박스로 구성합니다. 선택 요약과 검색·복수 선택을 제공하고 긴 목록은 내부에서 스크롤합니다. 오른쪽 패널에서는 목록을 본문 안에 펼쳐 잘리지 않게 합니다. Escape·바깥 클릭으로 닫고, 검색어는 저장하지 않습니다. 별도 UI 라이브러리는 사용하지 않습니다.

추천 체크박스에는 대상을 짧게 표시하고 복사·AI 전달 안내는 반복하지 않습니다. 상세 범위는 초안에 명시하며 전달 방법은 시작 안내와 기획 초안에서 안내합니다.

## 기획 초안의 화면 설정

초안의 AI 작업은 ‘AI에 전달할 프롬프트 보기’ 버튼 하나로 진입합니다. 네이티브 `dialog` 안에 기본/고급 스위치, ? 비교 도움말, 직접 수정 가능한 전체 프롬프트와 복사 버튼을 둡니다. 76px 너비의 스위치는 상태를 구분하기 쉽게 하고, ?는 28px로 작게 표시합니다. 별도 고급 편집 영역은 만들지 않습니다. 수정한 경우에만 ‘복원하기’를 표시하고 현재 모드만 확인 후 복원합니다. 긴 안내는 ? 안에 둡니다. 창의 제목·닫기·복사 버튼은 긴 본문을 스크롤해도 유지하고, Escape와 닫기 후 진입 버튼으로 초점을 돌립니다. 06에는 마무리 메모만 남깁니다.

? 비교 도움말은 ‘요청 범위 → 장점 → 고려할 점’ 순서로 구성합니다. PC에서는 기본·고급을 같은 너비의 열에 놓고 비교 항목을 같은 행에 맞춥니다. 열 제목·한 줄 요약·행 제목·본문을 글자 크기와 굵기, 구분선으로 구별합니다. 600px 이하에서는 항목마다 기본·고급을 세로로 짝지어 읽게 하며, 공통 안내는 표 아래로 분리합니다. HTML 표의 행·열 제목은 좁은 화면에서도 보조기기가 읽을 수 있게 유지합니다.

질문 안에서 화면 → 요소 → 입력 항목·동작의 계층을 유지합니다. 화면은 제목과 구분선, 요소는 테두리, 항목·동작은 배경이 있는 묶음으로 구분합니다. 포함 관계·순서를 먼저 보여 주고 같은 번호로 세부 설정을 연결합니다. 여러 줄의 선택지·자연어 설명·배치 구조는 줄바꿈과 들여쓰기를 유지하고, 비어 있는 세부 설정을 반복 표시하지 않습니다. 미리보기와 복사·파일의 정보가 달라지지 않도록 같은 초안 텍스트를 사용합니다.
